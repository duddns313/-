# 모험가 이야기형 개편 계획서 — v1

## 0. 한 문장

**허브를 돌아다니며 장면을 고르는 비주얼노벨**을 폐기하고,
**진행도 게이지 하나가 앞으로만 흐르며 그 위에 랜덤 인카운터가 쏟아지고
문턱마다 고정 스토리가 끼어드는 텍스트 로그라이크**로 바꾼다.

한 판 30~50분. 죽거나 진행도 100%면 끝. 엔딩을 모은다.

---

## 1. 원작 구조 분석 — 「모험가 이야기」 (스튜디오 휠)

리서치로 확인한 실제 작동 방식이다.

| 요소 | 원작의 처리 |
|---|---|
| 진행 축 | 경험치 = **모험 진행도(0→100%)**. 100% 도달 시 게임 종료 |
| 이벤트 | 대부분 랜덤. **배경에 따라 진행도가 일정 수준에 닿을 때마다 고정 이벤트 발생** |
| 종료 | 체력 0 · 정신력 0 · 진행도 100% · 중요 이벤트 승/패 → 각각 다른 엔딩 |
| 선택지 | ①무조건 ②능력치 확률 판정 ③**조건부**(스탯 수치·아이템·어빌리티 보유 시에만 노출) |
| 능력치 | 6종, 레벨업마다 보너스 포인트 분배 |
| 전투 | d20 굴림. 10 초과 = 공/방 이득, 9 이하 = 손해, **20 = 무조건 승리** |
| 배경 | 시작 시 1개 고정, 변경 불가. 배경이 고정 이벤트 세트와 엔딩 조건을 바꾼다 |
| 특성 | 시작 시 1개. 랜덤 인카운터로 **상위 특성 업그레이드** |
| 어빌리티 | 장비에 붙은 특수효과가 전투력을 결정 (선취점, 소매치기 등) |

### 핵심 통찰 ⭐

**"큰 스토리 라인"과 "랜덤 인카운트"는 별개 시스템이 아니다.
진행도 게이지 하나로 통합돼 있다.**

랜덤 인카운터가 진행도를 밀어올리고 → 진행도가 문턱을 넘으면 스토리가 강제로 끼어든다.
그래서 매 판 스토리는 같은 뼈대를 지나지만 그 사이를 채우는 살은 매번 다르다.

이 한 줄이 개편의 전부다. 나머지는 이걸 위한 정리다.

## 2. 세계관 — 유지한다

문장은 전면 신규 집필하지만, **「잊힘의 물리학」 8개 규칙(STORY_BIBLE §1)은 그대로 간다.**
이 규칙이 이 게임의 정체성이고, 무엇보다 **로그라이크와 궁합이 완벽하다.**

- 규칙 2: 먹힌 사람은 **처음부터 없었던 것처럼** 세계가 재배열된다
  → 매 회차 등장인물 구성이 달라져도 서사적으로 정당하다
- 규칙 5: 영운은 **놓지 않기로 정했기 때문에** 붙들 수 있다
  → "기억하겠다"를 고를수록 강해지는 빌드. 회차마다 다른 이름을 붙들 수 있다
- 규칙 8: 기념비의 이름은 갱신에 실패하면 스스로 매끈해진다
  → 침식이 곧 진행도의 시각적 표현

**침식(erosion) 시스템은 폐기하지 않고 승격시킨다.** 아래 §4 참조.

## 3. 핵심 루프

한 턴 = 인카운터 하나.

```
┌─────────────────────────────────┐
│ 진행도 ███████░░░░░░░░  34%      │
│ 체력 42/60   명부 5명   Lv.4     │
└─────────────────────────────────┘

  (본문 3~5문단)

  ▸ 그냥 지나간다
  ▸ 말을 건다              매력 68%
  ▸ 이음매를 살핀다        [지식 12 이상]
  ▸ 수첩을 펼친다          [이디스의 수첩]

        ↓ 선택

  (결과 문단)  [지식 +2 · 진행도 +3]

        ↓ [계속]

  nextEncounter() → 다음 인카운터
```

### `nextEncounter()` — 스케줄러 ⭐

우선순위대로 검사한다. 이것이 "스토리 라인 + 랜덤"의 실제 구현이다.

```
1. 진행도가 다음 고정 비트의 임계값을 넘었는가?  → 고정 스토리 비트 강제
2. 예약된 후속 인카운터(체인)가 있는가?          → 그것
3. 그 외                                        → 가중 랜덤 추첨
```

3번의 추첨 규칙:
- 조건 필터를 통과한 것만 후보 (진행도 구간 · 보유 플래그 · 배경 · 이미 본 것 제외)
- 가중치는 진행도 구간에 따라 이동 — 초반엔 일상, 후반엔 전투/괴이 비중 상승
- **최근 8개 이력 제외** (연달아 같은 게 나오는 체감 방지)
- 풀이 고갈되면 `repeatable` 인카운터로 폴백

### 진행도 증가량

| 인카운터 종류 | 증가량 |
|---|---|
| 잡담·일상 | +1 |
| 사건·판정 | +2~3 |
| 전투 | +3~5 |
| 고정 스토리 비트 | +6~10 |

한 판 ≈ 40~60 인카운터 ≈ 30~50분.

## 4. 자원 3종 = 죽는 방법 3가지 ⭐

원작의 체력/정신력/진행도 3축을, 이 게임 고유의 침식으로 번안한다.

| 자원 | 표시 | 0이 되면 |
|---|---|---|
| **체력** | `42/60` | 사망 엔딩 (배경별로 문장이 다름) |
| **명부** | `5명` | **「혼자 남은 자」 엔딩** — 붙든 이름이 전부 지워짐 |
| **진행도** | `34%` | 100% 도달 → 최종 대면 → 배경별 엔딩 |

**명부가 정신력 자리에 들어간다.** 이게 이번 개편의 가장 좋은 부분이다.

- 진행도가 오를수록 침식 속도가 빨라진다 (원작의 정신력 압박을 그대로 재현)
- 이름을 붙드는 행동(`holdName`)은 체력이나 시간을 대가로 요구한다 → 3자원 저글링
- 붙든 이름 수가 판정 보정과 최종 엔딩 등급에 동시에 반영된다
- **이미 `js/systems/register.js`에 전부 구현돼 있다.** 임계값만 재조정하면 된다

## 5. 전투 — d20 + 주문 사슬 (유니콘 오버로드 방식) ⭐

### 설계 원리

유니콘 오버로드의 핵심은 "전투 중 조작"이 아니라 **전투 전 프로그래밍**이다.
스킬마다 발동 조건과 우선순위를 미리 짜두고, 전투는 자동으로 굴러간다.
플레이어의 실력 = 편성 실력.

이게 텍스트 게임과 궁합이 좋은 이유:
전투 결과가 주사위 하나가 아니라 **내가 짠 사슬이 굴러간 5~8줄짜리 로그**가 된다.
읽을 거리가 되고, 지면 "조건을 잘못 짰다"는 명확한 피드백이 온다.
그러면서도 흐름을 끊지 않는 **단판**이다.

### 편성 화면 (언제든 열 수 있음)

```
주문 사슬                        AP 3/3

1 ▸ 프로테고        [적 공격력 ≥ 내 방어력]
2 ▸ 익스펠리아무스   [첫 수]
3 ▸ 에피스키        [내 체력 50% 미만]
4 ▸ 스투페파이      [항상]
5 ▸ (비어 있음)

  ↑↓ 순서 변경 · 슬롯을 눌러 주문/조건 교체
```

- **슬롯 순서 = 우선순위.** 위에서부터 조건을 검사한다
- **AP** = 한 전투에서 발동 가능한 총 주문 수 (기본 3, 장비·특성·레벨로 최대 6)
- 슬롯 수는 기본 5, 최대 8

### 조건 목록

| 조건 | 설명 |
|---|---|
| 항상 | 무조건 발동 |
| 첫 수 | 아직 아무 주문도 안 나갔을 때 |
| 내 체력 50% / 25% 미만 | 치유·방어 트리거 |
| 적 체력 50% 미만 | 마무리 |
| 적 위험도 3 이상 | 강적 한정 고화력 |
| 적이 어둠 속성 | 패트로누스류 |
| 굴림 15 이상 | 우세할 때만 |
| 굴림 7 이하 | 열세일 때 방어 |
| 직전 주문 발동함 | 연계 |

### 해결 알고리즘

```
1. d20 굴림
     20 → 즉시 완승, 전리품 등급 +1  (원작 규칙 그대로)
      1 → 즉시 완패, 사슬 전체 무효
2. 우세도 = roll - 10          (양수 우세 / 음수 열세)
3. 슬롯을 위에서부터 순회, AP 소진까지:
     조건 만족 && 마력 충분 → 발동
     주문 효과가 전장 상태(내 체력·적 체력·방어막)를 갱신
     ⭐ 갱신된 상태가 다음 슬롯의 조건 판정에 반영된다
4. 누적 위력 + 우세도  vs  적 방어력 → 승패
5. 승리: 진행도 +N, 경험치, 전리품 / 패배: 체력 손실 또는 사망
```

3번의 **상태 갱신이 다음 조건에 반영되는 것**이 핵심이다.
이게 있어야 "프로테고가 먼저 나가 방어막이 생겼으니 에피스키 조건이 안 걸린다" 같은
상호작용이 생기고, 순서 배치가 실력이 된다.

### 출력 예시

```
── 늑대인간 (위험도 3) ──
  d20 → 14   우세 (+4)

  ① 프로테고        조건 충족 → 방어막 +6
  ② 익스펠리아무스   첫 수     → 적 무장해제, 적 공격력 -4
  ③ 스투페파이      항상      → 피해 12
  ④ 에피스키        체력 78%  → 미발동

  승리 · 체력 -6 · 진행도 +4
```

### 기존 자산

`js/data/spells.js`의 `power` / `shieldMult` / `healAmount` / `bonusVs` / `mpCost` /
숙련도 구간이 **그대로 재사용된다.** 데이터 재작성이 필요 없다.

## 6. 캐릭터 빌드

### 배경 (background) — 시작 시 1개, 변경 불가

**배경이 고정 스토리 비트 세트와 전용 엔딩을 결정한다.** 재플레이의 축이다.

| 배경 | 특전 | 대가 | 스토리 축 |
|---|---|---|---|
| **편입생** | 시작 스탯 자유 분배 | 아는 사람이 없다 (초반 명부 2명) | 기본 라인 — 아무것도 놓고 오지 않은 자 |
| **유족** | 침식 저항, 시작 명부 6명 | **특정 이름을 잃으면 즉시 엔딩** | 기념비에서 시작. 조부의 이름을 지킨다 |
| **기록관 견습** | 손글씨 단서 추가 노출, 지식 +3 | 체력 낮음 | 수첩·기록 라인. 규칙 3·4를 정면으로 다룬다 |
| **잔영에 닿은 아이** | 어둠 주문 해금, 잔영 감지 | 침식 가속 | 이미 한 번 먹혔다 돌아온 자 |

### 특성 (trait) — 시작 시 1개, 랜덤 인카운터로 상위 승급

| 기본 | → 상위 | 효과 |
|---|---|---|
| 끈질김 | 놓지 않는 손 | 침식 저항 → 침식 1단계 되돌리기 1회 |
| 눈썰미 | 이음매를 읽는 눈 | 조건부 선택지 추가 노출 → 판정 성공률 사전 정밀 표시 |
| 담대함 | 두려움을 모르는 | d20 최소값 보정 → 대실패 무효 |
| 평범함 | (승급 없음) | 대신 시작 스탯 총합 +4 |

### 스탯 — 기존 5종 유지

지식 · 용기 · 매력 · 민첩 · 행운.
원작은 6종이지만 이미 5종으로 전 콘텐츠가 짜여 있고 `check.js`가 검증돼 있다. 건드리지 않는다.
**레벨업마다 보너스 포인트 2점을 직접 분배**하는 방식만 신규 추가한다 (원작 방식).

## 7. 엔딩 수집

한 판이 짧으므로 엔딩이 곧 콘텐츠다. 최소 12종.

| 계열 | 조건 |
|---|---|
| 사망 4종 | 체력 0 — 배경별로 다른 문장 |
| 「혼자 남은 자」 | 명부 전멸 |
| 완주 4종 | 진행도 100% — 배경별 최종 대면 결과 |
| 조건부 3종 이상 | 특정 이름 전부 보존 / 어둠 주문 남용 / 상위 특성 4종 달성 등 |

- 도감 탭에 **엔딩 목록(미발견은 실루엣)** + 달성 조건 힌트
- 발견한 엔딩 수에 따라 다음 회차 시작 보너스 (원작의 계승 요소)

## 8. 유지 / 폐기 / 신규

### 그대로 재사용
- `systems/check.js` — 판정(성공률 사전표시·4단계 tier). 손대지 않는다
- `systems/register.js` — 침식·명부·붙들기. 임계값만 재조정
- `systems/item.js` `systems/loot.js` `data/rarity.js` — 6등급 파밍 + 접사
- `data/spells.js` — 주문 사슬이 그대로 쓴다
- `ui.js`의 타이프라이터 · 토스트 · 바텀시트 · 설정
- `state.js`의 저장/불러오기 뼈대

### 폐기
- `data/scenes.js` (2,710줄) — 장면 그래프 구조라 랜덤 추첨이 불가능
- `systems/scene.js` — 허브/이동/장면 라우팅 전체
- `ui.js`: `renderTravel()` `openMinimapSheet()` `renderHubStage()` `renderStoryStage()`
- `engine.js`: 턴제 전투 블록 (`combatCastSpell`~`enemyTurn`), 시간대·D-day 마감
- `state.js`: `currentHub` `sceneNext` `deadline` `deadlinePenaltyStacks`

  pool: 'common',              // 추첨 풀
  weight: 10,                  // 기본 가중치

  text: `...본문 3~5문단...`,

    { label: '초상화에 말을 건다',
      check: { stat: 'charm', dc: 10 },
      outcomes: {

## 11. 구현 순서

| Phase | 내용 | 검증 |
|---|---|---|
| **1** | 진행도 스케줄러 + 인카운터 추첨 + 세이브 v10. 파일럿 인카운터 20개 | 처음부터 끝까지 한 판이 굴러가는가 |
| **2** | d20 + 주문 사슬 + 편성 UI | 사슬 조건이 상태 갱신에 반응하는가 |
| **3** | 배경 4종 · 특성 8종 · 레벨업 분배 | 배경별로 다른 비트가 뜨는가 |
| **4** | 인카운터 대량 집필 (목표 120개) | 40~60턴 한 판에서 반복 체감이 없는가 |
| **5** | 엔딩 12종 + 도감 | 엔딩 조건이 전부 도달 가능한가 |
| **6** | 헤드리스 시뮬레이터로 밸런스 검증 | 3자원 사망 비율이 고르게 갈리는가 |

Phase 1~2가 이번 개편의 본체다. 3 이후는 분량 작업이다.

### 세이브

구조가 근본적으로 다르므로 **v10으로 올리고 하위 호환을 끊는다.**
(v9 → v10, `MIN_COMPATIBLE_VERSION = 10`)
로그라이크라 한 판이 짧으므로 저장 승계 부담이 없다.
대신 **엔딩 도감·특성 해금은 판과 분리된 별도 키에 영구 저장**한다.

## 12. 검증 기준

- [ ] 한 판이 40~60 인카운터, 30~50분 안에 끝난다
- [ ] 같은 인카운터가 한 판에 두 번 나오지 않는다 (`repeatable` 제외)
- [ ] 고정 스토리 비트 5개가 배경과 무관하게 반드시 전부 등장한다
- [ ] 3가지 사망(체력·명부·완주)이 모두 실제로 발생한다
- [ ] 주문 사슬을 바꾸면 같은 적 상대 승률이 눈에 띄게 달라진다
- [ ] 조건부 선택지가 스탯/아이템/어빌리티 3종 모두로 열린다
- [ ] 두 번째 판이 첫 판과 다르게 느껴진다
