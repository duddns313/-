# 내실 다지기 계획 (v3)

> 구현 지침서. 이번 문서의 주제는 **새 기능 추가가 아니라, 이미 있는 것들을 서로 연결하는 것**입니다.

---

## 0. 진단 — 이 게임의 진짜 문제

코드를 실제로 조사한 결과입니다. 추측이 아니라 근거가 있습니다.

### 0-1. 숫자들이 서로 대화하지 않는다 (핵심 문제)

| 수치 | 쌓이는 곳 | 실제로 읽히는 곳 | 판정 |
|---|---|---|---|
| **날짜(day)** | 모든 행동마다 +1 | **표시 + 일일과제 갱신뿐** | 🔴 완전한 장식 |
| **성향(alignment)** | 이벤트 19곳에서 증감 | **엔딩 분기 1줄뿐** | 🔴 게임 중엔 무의미 |
| **기력(stamina)** | 탐험/수업에서 소모 | 탐험 가능 여부만 | 🟡 휴식이 공짜라 무력화 |
| **호감도** | 대화 이벤트 | 엔딩 + 마일스톤 2개 | 🟡 약함 |
| **갈레온** | 전투·이벤트 | 상점·강화·뽑기 | 🟡 시뮬에서 300~2800G 잉여 |

> **그래서 무슨 일이 벌어지나**: 플레이어가 "성향 -8"을 보고도 아무 감흥이 없습니다. 게임이 끝날 때까지 그 숫자가 자기 삶에 아무 영향을 주지 않기 때문입니다. 40시간 뒤 엔딩 텍스트 한 줄이 바뀌는 건, 지금 이 순간의 선택을 무겁게 만들지 못합니다.

### 0-2. 기력이 무력한 이유 (사용자 지적 정확함)

```
휴식하기 → 체력·마력·기력 전부 100% 회복, 비용 0, 제약 0
```

기력이 하는 일은 **"가끔 휴식 버튼을 누르게 만드는 것"** 뿐입니다. 이건 선택이 아니라 **클릭 노동**입니다. 자원이 의미를 가지려면 **그 자원을 아끼면 다른 걸 얻고, 쓰면 다른 걸 잃어야** 합니다. 지금은 아껴도 얻는 게 없고 써도 잃는 게 없습니다.

### 0-3. 실패해도 잃는 게 없다

전투 사망 외에 게임을 "못하게" 되는 경로가 전혀 없습니다. 시뮬레이션 24회에서 패배는 1회뿐이었고, 그마저도 보스전 한정입니다. 위험을 감수할 이유도, 피할 이유도 약합니다.

### 0-4. 그 외 즉시 고칠 것

- **🔴 호칭 오류**: `story.js`에 "영운 **군**"이 4곳. 아내분께 드리는 선물인데 성별이 틀렸습니다. **최우선 수정.**
- **타자 스킵 영역**: `skipTypewriters`가 `#log-recent`(작은 로그 박스)에만 걸려 있습니다. 화면 아무 데나 눌러도 되게 해야 합니다.

## 1. 핵심 제안 — 시간을 화폐로 만들기 ⭐

**이것 하나가 위의 문제 대부분을 동시에 해결합니다.** 다른 모든 항목보다 우선입니다.

### 1-1. 마감(Deadline) 도입

덤블도어의 의뢰에 **기한**을 붙입니다.

> *"영운 양, 학생들이 계속 사라지고 있네. 시간이 없어."*

- 각 장(章)에 **제한 일수**를 부여 (예: 1장 30일, 2장 40일, 3장 50일)
- 남은 일수를 **상단바에 상시 표시** — 촉박해지면 붉게 점멸
- 기한을 넘기면 **즉시 실패가 아니라 악화**:
  - 실종 학생 수 증가 → 기숙사 점수 하락, 학교 분위기 악화 로그
  - 최종 보스 능력치 상승 (어둠이 더 자랐다)
  - 엔딩 등급 하락 (`light` → `balanced` 강등 등)

> **왜 즉사가 아니라 악화인가**: 아내분께 드리는 선물입니다. 시간 못 맞췄다고 게임 오버가 뜨면 재미가 아니라 스트레스입니다. "늦으면 더 힘들어진다" 정도가 긴장감과 관대함의 균형점입니다. 난이도 옵션으로 **'여유롭게' 모드(마감 없음)** 도 함께 제공하는 것을 권장합니다.

### 1-2. 휴식의 재설계 — 골드와 시간의 교환

이제 **휴식은 하루를 소모**합니다. 그리고 하루는 이제 값어치가 있습니다.

| 회복 수단 | 비용 | 하루 소모 | 회복량 |
|---|---|:---:|---|
| **휴게실에서 휴식** | 무료 | **1일** | 전체 회복 |
| **대연회장 식사** | 5G | **0일** | 기력 40 |
| **초콜릿 개구리** | 6G | 0일 | 기력 25 + 체력 15 |
| **원기 회복 물약**(신규) | 25G | 0일 | 기력 전체 |

> **이게 왜 결정인가**: *"돈을 아끼고 하루를 버릴 것인가, 갈레온을 태워 하루를 살 것인가."* 갈레온이 남아돌던 문제와 기력이 무의미하던 문제가 **동시에** 해결됩니다. 시뮬레이션에서 2,800G가 놀고 있던 게 이제 시간으로 환전됩니다.

### 1-3. 피로 누적 (선택 사항, 권장)

연속으로 휴식 없이 행동하면 `피로` 스택이 쌓여 **최대 기력이 일시적으로 감소**합니다. 무리하면 대가가 따르고, 며칠 푹 쉬면 회복됩니다. 밤샘 벼락치기의 감각을 줍니다.

**영향 파일**: `js/state.js`(deadline/fatigue 필드), `js/engine.js`(rest/explore/attendClass), `js/systems/time.js`(신규), `js/ui.js`(상단바 D-day)

## 2. 기억 시스템 — 선택이 나중에 돌아오게 ⭐

사용자 요청의 핵심: *"이 선택이 추후 선택에 영향을 미치거나… 이럴 때는 예전에 이 선택이 영향을 끼친다고 보여줘야 기억에 남음"*

### 2-1. 구조

```js
// 선택할 때 기억을 남긴다
{ label: '헤르미온느를 구하러 달려간다',
  effect: { memory: 'saved_hermione', companionAffinity: {...} } }

// 나중에 그 기억을 참조한다
{ id: 'hermione_crisis',
  recall: 'saved_hermione',                    // ← 회상 배너 표시
  recallText: '트롤에게서 헤르미온느를 구했던 그날 밤이 스친다.',
  choices: [
    { label: '"나를 믿어."',
      requiresMemory: 'saved_hermione',        // ← 그때 구했어야만 열리는 선택지
      check: { stat: 'charm', dc: 6, bonus: 3 } }   // ← 또는 판정 보정
  ] }
```

### 2-2. 연출이 핵심

기억이 발동하면 **눈에 띄게 보여줘야** 합니다. 조용히 확률만 바뀌면 플레이어는 영원히 모릅니다.

```
┌─────────────────────────────┐
│ 💭 그때의 선택이 떠오른다      │
│ 트롤에게서 헤르미온느를 구했던  │
│ 그날 밤 —                    │
└─────────────────────────────┘
헤르미온느가 망설임 없이 고개를 끄덕인다.
[설득 · 성공률 78%  (기억 보정 +15%)]
```

- 회상 배너는 전용 스타일(금색 테두리 + 💭)
- 판정 보정이 붙으면 성공률 옆에 **`(기억 보정 +15%)`** 를 명시
- **캐릭터 탭에 "기억" 목록** — 지금까지 내린 결정적 선택들이 연대기처럼 쌓임

### 2-3. 심을 만한 기억 (예시)

| 기억 | 남는 순간 | 나중에 |
|---|---|---|
| `saved_hermione` | 핼러윈 트롤에서 구하러 감 | 헤르미온느 관련 판정 보정, 전용 선택지 |
| `refused_beggar` | 방랑자를 외면함 | 그 방랑자가 다시 등장, 도움을 거절당함 |
| `read_dark_book` | 금서 구역에서 어둠의 지식 습득 | 어둠 주문 판정 보정 + 교수의 의심 이벤트 |
| `broke_curfew` | 통금 위반 적발 | 이후 반장 이벤트 난이도 상승 |
| `kept_promise_neville` | 네빌의 책을 찾아줌 | 결전에서 네빌이 자발적으로 도우러 옴 |

**영향 파일**: `js/systems/memory.js`(신규), `js/data/events.js`, `js/engine.js`, `js/ui.js`, `css/style.css`

## 3. 다단계 퀘스트 시스템

사용자 요청: *"단 한번의 선택지로 끝내지 말고, 서로 연계되거나, 연달아 시도해야 하거나"*

### 3-1. 세 가지 퀘스트 형태

| 형태 | 구조 | 예시 |
|---|---|---|
| **수집형** | 서로 다른 장소에서 재료 N종 → 조합 판정 | 마법약 조제: 약초(숲)+뿔가루(상점)+달빛물(밤) → 조제 |
| **연속 도전형** | **연속 성공** N회 필요, 실패 시 진행도 리셋 | 패트로누스 수련: 3회 연속 성공해야 습득 |
| **분기형** | 중간 선택이 최종 결과를 바꿈 | 실종 사건 조사: 누구를 먼저 의심하느냐로 진범 루트 분기 |

**연속 도전형**을 특히 권장합니다. *"두 번 성공했는데 세 번째에 실패"* 는 텍스트 게임에서 만들 수 있는 가장 값싼 긴장감입니다.

### 3-2. 퀘스트 로그 UI (필수)

지금은 진행 중인 퀘스트가 뭔지 확인할 방법이 없습니다. **모험 탭 상단에 현재 목표를 상시 표시**해야 합니다.

```
📜 진행 중
  · [메인] 단서를 찾아라 — 도서관/복도 (D-12)
  · 네빌의 교과서 찾기 (1/1 발견, 돌려주러 가기)
  · 패트로누스 수련 (연속 2/3)
```

**영향 파일**: `js/systems/quest.js`(신규), `js/data/quests.js`(신규), `js/ui.js`

## 4. 이벤트 우선순위 3단계

사용자 요청: *"대형 퀘스트보다 먼저 되어야 할 게 메인 퀘스트야"*

현재 `priority`가 true/false 뿐이라 메인 스토리와 대형 이벤트가 같은 급으로 경쟁합니다.

```js
priority: 3  // 메인 퀘스트 (최우선 — 이게 밀리면 안 됨)
priority: 2  // 대형 이벤트 (핼러윈 트롤, 퀴디치, 무도회)
priority: 1  // 사이드 퀘스트 (네빌의 책, 해그리드의 부탁)
priority: 0  // 잡 이벤트 (기본값)
```

선택 로직: **가장 높은 등급의 후보군만 남기고 그 안에서 랜덤.** 한 줄 수정으로 끝납니다.

## 5. 따뜻하고 귀여운 이벤트 + 원작 인물

사용자 요청: *"기분 좋고 귀여운 이벤트들과, 책 속 등장인물과의 상호작용"*

### 5-1. 설계 원칙

이 이벤트들은 **실패해도 손해가 없어야** 합니다. 게임의 긴장은 1번(마감)이 담당하고, 이 이벤트들은 **쉼표** 역할입니다. 판정을 넣더라도 실패는 "조금 덜 귀여운 결과"일 뿐이어야 합니다.

### 5-2. 아직 안 쓴 원작 인물들

| 인물 | 이벤트 아이디어 |
|---|---|
| **도비** | 양말을 선물하면 감격해서 울며 은혜를 갚음(이후 위기에서 등장) |
| **헤드위그** | 부엉이장에서 쓰다듬기, 편지를 물어다 줌 |
| **크룩섕스** | 도서관에서 무릎에 올라와 잠듦 → 그동안 공부 효율 상승 |
| **프레드 & 조지** | 장난 상품 시식 실험 참가 (랜덤 코믹 효과) |
| **니어리 헤들리스 닉** | 데스데이 파티 초대 |
| **뚱뚱한 귀부인** | 암호를 잊어버려 초상화 앞에서 실랑이 |
| **맥고나걸** | 엄격하지만 다정한 격려, 변신술 개인 지도 |
| **스프라우트** | 온실에서 맨드레이크 분갈이 (귀마개 필수!) |
| **트릴로니** | 황당한 점괘 (가끔 진짜로 맞음) |
| **버클비크** | 정중히 인사하면 태워줌 |
| **니플러** | 반짝이는 걸 훔쳐감 → 쫓아가면 보물더미 발견 |
| **해그리드** | 이미 있음 — 애완동물 자랑 이벤트 추가 |

### 5-3. "따뜻한 기억" 수집

귀여운 이벤트를 겪을 때마다 **추억 카드**가 도감에 쌓이도록 합니다. 전투나 파밍과 무관한, **순수하게 모으는 재미**의 축입니다. 선물로서의 성격에도 잘 맞습니다.

## 6. 게이지 이펙트 (게임 필)

사용자 요청: *"기력바나 체력바가 주는 이펙트… 연해지면서 날아간다든지"*

| 상황 | 연출 |
|---|---|
| 피격 | 바가 좌우로 **흔들리고**, 깎인 구간이 **흰색 잔상**으로 남았다가 스르륵 사라짐 |
| 피해 수치 | `-12` 가 위로 **떠오르며 페이드아웃** |
| 회복 | 초록빛이 바를 따라 **번짐** |
| 기력 소모 | 바가 잠깐 **연해졌다 복귀**(pulse) |
| 체력 위험(<25%) | 바가 **붉게 천천히 점멸** |
| 마감 임박 | 상단 D-day가 **붉게 점멸** |

전부 CSS 애니메이션 + 짧은 JS로 가능하며, 외부 라이브러리가 필요 없습니다. `prefers-reduced-motion`은 반드시 존중해야 합니다.

> **2번만 해도 게임이 달라집니다.** 나머지는 그 위에 쌓는 것입니다.

## 9. 하지 말자고 제안하는 것

내실을 다지려면 **안 하는 것**도 정해야 합니다.

- ❌ **새 스탯 추가** — 5개도 이미 서로 잘 안 엮입니다. 늘리지 말고 엮으세요.
- ❌ **Phase 5 시간표(오전/오후/야간) 전면 도입** — 마감 시스템과 역할이 겹칩니다. 마감을 먼저 넣고, 그래도 부족하면 그때 검토.
- ❌ **전투 시스템 대수술(상태이상·태세)** — 현재 전투는 전체 플레이의 일부일 뿐입니다. 마감·기억이 훨씬 체감이 큽니다. 후순위로.
- ❌ **세트 아이템 / 저주 아이템 / 마법약 조제** — 파밍 축은 이미 충분히 두껍습니다.
- ❌ **이벤트 개수 목표치(120개 등) 채우기** — 42개짜리 얕은 이벤트보다 **연계되는 20개**가 낫습니다. 3번을 하고 나서 다시 이야기.
