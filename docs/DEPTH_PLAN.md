# 내실 다지기 계획 (v3)

> 구현 지침서. 이번 문서의 주제는 **새 기능 추가가 아니라, 이미 있는 것들을 서로 연결하는 것**입니다.

## ✅ 확정된 결정

- **마감 시스템을 기본으로 채택.** '여유롭게' 모드는 만들지 않는다(원하면 나중에).
- **기한 초과 페널티는 엔딩 강등까지.** 보스 강화 + 실종자 누적 + 최종 엔딩 등급 하락.
- **호칭은 "영운 양".** 주인공은 여성. 모든 텍스트를 이 기준으로 점검한다.
- 이동 시스템 전면 개편(§11), 이벤트 망 구축(§12)을 추가 범위로 포함.

## 0. 진단 — 이 게임의 진짜 문제

코드를 실제로 조사한 결과입니다. 추측이 아니라 근거가 있습니다.

### 0-1. 숫자들이 서로 대화하지 않는다 (핵심 문제)

| 수치 | 쌓이는 곳 | 실제로 읽히는 곳 | 판정 |
|---|---|---|---|
| **날짜(day)** | 모든 행동마다 +1 | **표시 + 일일과제 갱신뿐** | 🔴 완전한 장식 |
| **성향(alignment)** | 이벤트 19곳에서 증감 | **엔딩 분기 1줄뿐** | 🔴 게임 중엔 무의미 |
| **기력(stamina)** | 탐험/수업에서 소모 | 탐험 가능 여부만 | 🟡 휴식이 공짜라 무력화 |
| **호감도** | 대화 이벤트 | 엔딩 + 마일스톤 2개 | 🟡 약함 |
| **갈레온** | 전투·이벤트 | 상점·강화·뽑기 | 🟡 시뮬에서 300~2800G 잉여 |

> **그래서 무슨 일이 벌어지나**: 플레이어가 "성향 -8"을 보고도 아무 감흥이 없습니다. 게임이 끝날 때까지 그 숫자가 자기 삶에 아무 영향을 주지 않기 때문입니다. 40시간 뒤 엔딩 텍스트 한 줄이 바뀌는 건, 지금 이 순간의 선택을 무겁게 만들지 못합니다.

### 0-2. 기력이 무력한 이유 (사용자 지적 정확함)

```
휴식하기 → 체력·마력·기력 전부 100% 회복, 비용 0, 제약 0
```

기력이 하는 일은 **"가끔 휴식 버튼을 누르게 만드는 것"** 뿐입니다. 이건 선택이 아니라 **클릭 노동**입니다. 자원이 의미를 가지려면 **그 자원을 아끼면 다른 걸 얻고, 쓰면 다른 걸 잃어야** 합니다. 지금은 아껴도 얻는 게 없고 써도 잃는 게 없습니다.

### 0-3. 실패해도 잃는 게 없다

전투 사망 외에 게임을 "못하게" 되는 경로가 전혀 없습니다. 시뮬레이션 24회에서 패배는 1회뿐이었고, 그마저도 보스전 한정입니다. 위험을 감수할 이유도, 피할 이유도 약합니다.

### 0-4. 그 외 즉시 고칠 것

- **🔴 호칭 오류**: `story.js`에 "영운 **군**"이 4곳. 아내분께 드리는 선물인데 성별이 틀렸습니다. **최우선 수정.**
- **타자 스킵 영역**: `skipTypewriters`가 `#log-recent`(작은 로그 박스)에만 걸려 있습니다. 화면 아무 데나 눌러도 되게 해야 합니다.

## 1. 핵심 제안 — 시간을 화폐로 만들기 ⭐

**이것 하나가 위의 문제 대부분을 동시에 해결합니다.** 다른 모든 항목보다 우선입니다.

### 1-1. 마감(Deadline) 도입

덤블도어의 의뢰에 **기한**을 붙입니다.

> *"영운 양, 학생들이 계속 사라지고 있네. 시간이 없어."*

- 각 장(章)에 **제한 일수**를 부여 (예: 1장 30일, 2장 40일, 3장 50일)
- 남은 일수를 **상단바에 상시 표시** — 촉박해지면 붉게 점멸
- 기한을 넘기면 **즉시 실패가 아니라 악화**:
  - 실종 학생 수 증가 → 기숙사 점수 하락, 학교 분위기 악화 로그
  - 최종 보스 능력치 상승 (어둠이 더 자랐다)
  - 엔딩 등급 하락 (`light` → `balanced` 강등 등)

> **왜 즉사가 아니라 악화인가**: 아내분께 드리는 선물입니다. 시간 못 맞췄다고 게임 오버가 뜨면 재미가 아니라 스트레스입니다. "늦으면 더 힘들어진다" 정도가 긴장감과 관대함의 균형점입니다. 난이도 옵션으로 **'여유롭게' 모드(마감 없음)** 도 함께 제공하는 것을 권장합니다.

### 1-2. 휴식의 재설계 — 골드와 시간의 교환

이제 **휴식은 하루를 소모**합니다. 그리고 하루는 이제 값어치가 있습니다.

| 회복 수단 | 비용 | 하루 소모 | 회복량 |
|---|---|:---:|---|
| **휴게실에서 휴식** | 무료 | **1일** | 전체 회복 |
| **대연회장 식사** | 5G | **0일** | 기력 40 |
| **초콜릿 개구리** | 6G | 0일 | 기력 25 + 체력 15 |
| **원기 회복 물약**(신규) | 25G | 0일 | 기력 전체 |

> **이게 왜 결정인가**: *"돈을 아끼고 하루를 버릴 것인가, 갈레온을 태워 하루를 살 것인가."* 갈레온이 남아돌던 문제와 기력이 무의미하던 문제가 **동시에** 해결됩니다. 시뮬레이션에서 2,800G가 놀고 있던 게 이제 시간으로 환전됩니다.

### 1-3. 피로 누적 (선택 사항, 권장)

연속으로 휴식 없이 행동하면 `피로` 스택이 쌓여 **최대 기력이 일시적으로 감소**합니다. 무리하면 대가가 따르고, 며칠 푹 쉬면 회복됩니다. 밤샘 벼락치기의 감각을 줍니다.

**영향 파일**: `js/state.js`(deadline/fatigue 필드), `js/engine.js`(rest/explore/attendClass), `js/systems/time.js`(신규), `js/ui.js`(상단바 D-day)

## 2. 기억 시스템 — 선택이 나중에 돌아오게 ⭐

사용자 요청의 핵심: *"이 선택이 추후 선택에 영향을 미치거나… 이럴 때는 예전에 이 선택이 영향을 끼친다고 보여줘야 기억에 남음"*

### 2-1. 구조

```js
// 선택할 때 기억을 남긴다
{ label: '헤르미온느를 구하러 달려간다',
  effect: { memory: 'saved_hermione', companionAffinity: {...} } }

// 나중에 그 기억을 참조한다
{ id: 'hermione_crisis',
  recall: 'saved_hermione',                    // ← 회상 배너 표시
  recallText: '트롤에게서 헤르미온느를 구했던 그날 밤이 스친다.',
  choices: [
    { label: '"나를 믿어."',
      requiresMemory: 'saved_hermione',        // ← 그때 구했어야만 열리는 선택지
      check: { stat: 'charm', dc: 6, bonus: 3 } }   // ← 또는 판정 보정
  ] }
```

### 2-2. 연출이 핵심

기억이 발동하면 **눈에 띄게 보여줘야** 합니다. 조용히 확률만 바뀌면 플레이어는 영원히 모릅니다.

```
┌─────────────────────────────┐
│ 💭 그때의 선택이 떠오른다      │
│ 트롤에게서 헤르미온느를 구했던  │
│ 그날 밤 —                    │
└─────────────────────────────┘
헤르미온느가 망설임 없이 고개를 끄덕인다.
[설득 · 성공률 78%  (기억 보정 +15%)]
```

- 회상 배너는 전용 스타일(금색 테두리 + 💭)
- 판정 보정이 붙으면 성공률 옆에 **`(기억 보정 +15%)`** 를 명시
- **캐릭터 탭에 "기억" 목록** — 지금까지 내린 결정적 선택들이 연대기처럼 쌓임

### 2-3. 심을 만한 기억 (예시)

| 기억 | 남는 순간 | 나중에 |
|---|---|---|
| `saved_hermione` | 핼러윈 트롤에서 구하러 감 | 헤르미온느 관련 판정 보정, 전용 선택지 |
| `refused_beggar` | 방랑자를 외면함 | 그 방랑자가 다시 등장, 도움을 거절당함 |
| `read_dark_book` | 금서 구역에서 어둠의 지식 습득 | 어둠 주문 판정 보정 + 교수의 의심 이벤트 |
| `broke_curfew` | 통금 위반 적발 | 이후 반장 이벤트 난이도 상승 |
| `kept_promise_neville` | 네빌의 책을 찾아줌 | 결전에서 네빌이 자발적으로 도우러 옴 |

**영향 파일**: `js/systems/memory.js`(신규), `js/data/events.js`, `js/engine.js`, `js/ui.js`, `css/style.css`

## 3. 다단계 퀘스트 시스템

사용자 요청: *"단 한번의 선택지로 끝내지 말고, 서로 연계되거나, 연달아 시도해야 하거나"*

### 3-1. 세 가지 퀘스트 형태

| 형태 | 구조 | 예시 |
|---|---|---|
| **수집형** | 서로 다른 장소에서 재료 N종 → 조합 판정 | 마법약 조제: 약초(숲)+뿔가루(상점)+달빛물(밤) → 조제 |
| **연속 도전형** | **연속 성공** N회 필요, 실패 시 진행도 리셋 | 패트로누스 수련: 3회 연속 성공해야 습득 |
| **분기형** | 중간 선택이 최종 결과를 바꿈 | 실종 사건 조사: 누구를 먼저 의심하느냐로 진범 루트 분기 |

**연속 도전형**을 특히 권장합니다. *"두 번 성공했는데 세 번째에 실패"* 는 텍스트 게임에서 만들 수 있는 가장 값싼 긴장감입니다.

### 3-2. 퀘스트 로그 UI (필수)

지금은 진행 중인 퀘스트가 뭔지 확인할 방법이 없습니다. **모험 탭 상단에 현재 목표를 상시 표시**해야 합니다.

```
📜 진행 중
  · [메인] 단서를 찾아라 — 도서관/복도 (D-12)
  · 네빌의 교과서 찾기 (1/1 발견, 돌려주러 가기)
  · 패트로누스 수련 (연속 2/3)
```

**영향 파일**: `js/systems/quest.js`(신규), `js/data/quests.js`(신규), `js/ui.js`

## 4. 이벤트 우선순위 3단계

사용자 요청: *"대형 퀘스트보다 먼저 되어야 할 게 메인 퀘스트야"*

현재 `priority`가 true/false 뿐이라 메인 스토리와 대형 이벤트가 같은 급으로 경쟁합니다.

```js
priority: 3  // 메인 퀘스트 (최우선 — 이게 밀리면 안 됨)
priority: 2  // 대형 이벤트 (핼러윈 트롤, 퀴디치, 무도회)
priority: 1  // 사이드 퀘스트 (네빌의 책, 해그리드의 부탁)
priority: 0  // 잡 이벤트 (기본값)
```

선택 로직: **가장 높은 등급의 후보군만 남기고 그 안에서 랜덤.** 한 줄 수정으로 끝납니다.

## 5. 따뜻하고 귀여운 이벤트 + 원작 인물

사용자 요청: *"기분 좋고 귀여운 이벤트들과, 책 속 등장인물과의 상호작용"*

### 5-1. 설계 원칙

이 이벤트들은 **실패해도 손해가 없어야** 합니다. 게임의 긴장은 1번(마감)이 담당하고, 이 이벤트들은 **쉼표** 역할입니다. 판정을 넣더라도 실패는 "조금 덜 귀여운 결과"일 뿐이어야 합니다.

### 5-2. 아직 안 쓴 원작 인물들

| 인물 | 이벤트 아이디어 |
|---|---|
| **도비** | 양말을 선물하면 감격해서 울며 은혜를 갚음(이후 위기에서 등장) |
| **헤드위그** | 부엉이장에서 쓰다듬기, 편지를 물어다 줌 |
| **크룩섕스** | 도서관에서 무릎에 올라와 잠듦 → 그동안 공부 효율 상승 |
| **프레드 & 조지** | 장난 상품 시식 실험 참가 (랜덤 코믹 효과) |
| **니어리 헤들리스 닉** | 데스데이 파티 초대 |
| **뚱뚱한 귀부인** | 암호를 잊어버려 초상화 앞에서 실랑이 |
| **맥고나걸** | 엄격하지만 다정한 격려, 변신술 개인 지도 |
| **스프라우트** | 온실에서 맨드레이크 분갈이 (귀마개 필수!) |
| **트릴로니** | 황당한 점괘 (가끔 진짜로 맞음) |
| **버클비크** | 정중히 인사하면 태워줌 |
| **니플러** | 반짝이는 걸 훔쳐감 → 쫓아가면 보물더미 발견 |
| **해그리드** | 이미 있음 — 애완동물 자랑 이벤트 추가 |

### 5-3. "따뜻한 기억" 수집

귀여운 이벤트를 겪을 때마다 **추억 카드**가 도감에 쌓이도록 합니다. 전투나 파밍과 무관한, **순수하게 모으는 재미**의 축입니다. 선물로서의 성격에도 잘 맞습니다.

## 6. 게이지 이펙트 (게임 필)

사용자 요청: *"기력바나 체력바가 주는 이펙트… 연해지면서 날아간다든지"*

| 상황 | 연출 |
|---|---|
| 피격 | 바가 좌우로 **흔들리고**, 깎인 구간이 **흰색 잔상**으로 남았다가 스르륵 사라짐 |
| 피해 수치 | `-12` 가 위로 **떠오르며 페이드아웃** |
| 회복 | 초록빛이 바를 따라 **번짐** |
| 기력 소모 | 바가 잠깐 **연해졌다 복귀**(pulse) |
| 체력 위험(<25%) | 바가 **붉게 천천히 점멸** |
| 마감 임박 | 상단 D-day가 **붉게 점멸** |

전부 CSS 애니메이션 + 짧은 JS로 가능하며, 외부 라이브러리가 필요 없습니다. `prefers-reduced-motion`은 반드시 존중해야 합니다.

| **4** | **기억 시스템 + 회상 연출** | 선택에 무게를 주는 핵심 |
| **5** | 퀘스트 로그 UI + 다단계 퀘스트 | 4번 없이는 만들어도 안 보임 |
| **6** | 게이지 이펙트 | 폴리시 |
| **7** | 귀여운 이벤트 + 원작 인물 | 시스템 확정 후 콘텐츠 투입 |
| **8** | 시뮬레이터 재실행 → 마감 밸런스 검증 | 마감 일수는 반드시 시뮬로 조정 |

> **2번만 해도 게임이 달라집니다.** 나머지는 그 위에 쌓는 것입니다.

## 11. 이동 시스템 전면 개편 ⭐

> 지적: *"맵 이동할 때 어디에서 어디로 연결되는지 알 길이 없음"*, *"이동하는 게 뭔가 흥미롭지 않아"*

### 11-1. 왜 지루한가 (원인 분석)

지금 이동은 **버튼 나열 → 즉시 순간이동**입니다. 네 가지가 전부 빠져 있습니다.

| 빠진 것 | 결과 |
|---|---|
| 공간 인지 | 호그와트가 머릿속에 안 그려짐. 도서관이 숲에서 먼지 가까운지 모름 |
| 비용 | 무료·무제한이라 결정이 아니라 **메뉴 선택** |
| 도중의 내용 | 이동하는 동안 아무 일도 안 일어남 |
| 목적 | 어디를 가야 할 이유가 없음. 그래서 무작위로 누름 |

### 11-2. 목적지 힌트 — 가장 효과 큰 한 방 ⭐

**이동이 지루한 진짜 이유는 "어디를 가야 할지 모르기 때문"입니다.** 목적 없는 이동은 방황이지 탐험이 아닙니다.

각 목적지 버튼에 **거기서 뭘 할 수 있는지 미리 표시**합니다.

```
이동
┌────────────────┬────────────────┐
│ 교장실      ⭐  │ 도서관      ❗  │
│ 안전 · 기력3    │ 안전 · 기력3    │
│ 메인 퀘스트     │ 조사할 단서     │
├────────────────┼────────────────┤
│ 금지된 숲   ☠️  │ 호그스미드  🏪  │
│ 위험 · 기력12   │ 주의 · 기력8    │
│                │ 상점            │
└────────────────┴────────────────┘
```

- ⭐ 메인 퀘스트 대기 중 / ❗ 사이드 퀘스트 대기 중 / 🏪 상점 / 🛏️ 휴식 / 🪄 수업
- 힌트는 **`priority` 값을 그대로 재활용**하면 됩니다 (§4에서 3단계로 나눈 것)
- 이러면 이동이 **방황 → 목표를 향한 항해**로 바뀝니다

### 11-3. 텍스트 미니맵 (구역 기반)

모바일 390px에 ASCII 격자를 그리면 깨집니다. **구역(zone)으로 묶은 세로 목록**이 답입니다.

```
┌ 🏰 성 내부 ─────────────────┐
│   대연회장     안전   🍽️     │
│   기숙사 휴게실 안전   🛏️     │
│   도서관       안전   ❗     │
│   주문학 교실   안전   🪄     │
│   교장실       안전   ⭐     │
│ ▶ 성의 복도     주의   ← 여기 │
└─────────────────────────────┘
          ↕ 기력 8
┌ 🌲 교외 ────────────────────┐
│   호그스미드    주의   🏪     │
│   금지된 숲     위험   ☠️     │
└─────────────────────────────┘
          ↕ 기력 12
┌ 🔒 비밀의 방 ───────────────┐
│   ??? — 아직 갈 수 없다      │
└─────────────────────────────┘
```

- 데이터에 `zone` 필드 추가 (`castle` / `outskirts` / `deep`)
- **미발견 구역은 `???`** 로 가림 → 지도를 채우는 재미
- 모험 탭 상단의 접이식 패널, 또는 이동 버튼 옆 🗺️ 아이콘 → 바텀시트

### 11-4. 이동 비용 — 기력으로

마감 경제(§1)와 맞물립니다. **날짜가 아니라 기력**으로 받아야 합니다(날짜로 받으면 이동 3번에 3일이 날아가 너무 가혹).

| 구간 | 기력 |
|---|:---:|
| 같은 구역 안 (예: 도서관 → 대연회장) | 3 |
| 성 ↔ 교외 | 8 |
| 교외 → 금지된 숲 / 비밀의 방 | 12 |

> 숫자는 반드시 **시뮬레이터로 검증 후 조정**할 것. 이동이 탐험보다 비싸지면 안 됩니다.

### 11-5. 이동 중 조우

구역을 **넘을 때** 낮은 확률로 짧은 이벤트가 발생합니다. 이동 자체가 콘텐츠가 됩니다.

- *"움직이는 계단에 발이 묶여 한참을 돌아갔다."* (기력 추가 소모)
- *"복도에서 니어리 헤들리스 닉과 마주쳤다."* (귀여운 이벤트로 연결)
- *"필치와 노리스 부인이 저쪽에서 걸어온다."* (민첩 판정 — 통금 시간이면 위험)

### 11-6. 도둑 지도 — 이동의 성장 축 ⭐

**`marauderMap`은 이미 아이템 데이터에 존재하는데 아무 기능이 없습니다.** 여기에 역할을 주면 공짜로 콘텐츠가 생깁니다.

| 해금 | 효과 |
|---|---|
| **도둑 지도 획득** | 미니맵에 **비밀 통로** 표시 → 성 내부 이동 기력 3 → **1** |
| | 이동 중 조우에서 **필치·반장 회피 가능** (사전 경고) |
| | 특정 장소·이벤트 해금 |

획득 경로는 원작대로 **프레드 & 조지**에게서 받습니다(§12-3 체인).

**영향 파일**: `js/data/locations.js`(zone·비용), `js/systems/travel.js`(신규), `js/ui.js`(미니맵·목적지 카드), `css/style.css`

## 12. 이벤트 망(Web) — 원작 적극 활용 ⭐

> 지적: *"이벤트가 더 많고 서로 영향을 끼쳤으면 좋겠어. 소설과 영화를 적극 활용해서"*

### 12-1. 원칙 — 목록이 아니라 망

**개수를 세지 말고 연결을 세야 합니다.** 독립된 이벤트 100개보다, 서로를 참조하는 30개가 훨씬 깊습니다. 모든 신규 이벤트는 아래 셋 중 최소 하나를 만족해야 합니다.

1. **기억을 남긴다** (`memory`) — 나중에 참조될 씨앗
2. **기억을 참조한다** (`recall`) — 과거를 불러와 지금을 바꿈
3. **체인의 일부다** — 앞 노드 없이는 등장하지 않음

### 12-2. NPC 상태 추적

동료 호감도(0~100)와 별개로, **NPC마다 상태 플래그**를 둡니다.

```js
state.npc = {
  dobby:   { met: true, warned: true, freed: false },
  weasleyTwins: { pranked: true, trust: 2 },
  filch:   { caught: 1 },       // 걸린 횟수 → 이후 난이도 상승
  malfoy:  { rivalry: 3 },      // 갈등 누적 → 결투 이벤트 발생
}
```

이 상태를 이벤트가 읽고 쓰면서 **세계가 나를 기억하는 느낌**이 생깁니다.

### 12-3. 구축할 체인 (원작 1~3학년 기반)

각 체인은 **3~5개 노드**로 구성되며, 앞 노드의 선택이 뒤를 바꿉니다.

#### ① 보가트 → 두려움 → 패트로누스 (⭐ 가장 추천)
| 노드 | 내용 |
|---|---|
| 1. 어둠의 마법 방어술 수업 | 보가트가 **내 두려움**으로 변신 — 무엇으로 변할지 **플레이어가 선택** (거미/어둠/실패/상실) |
| 2. `리들리쿠러스!` | 웃음으로 물리치기 판정. 선택한 두려움이 `memory`로 기록 |
| 3. 디멘터 조우 | 💭 회상 발동 — 그때 고른 두려움이 환청으로 들려옴 (개인화된 텍스트) |
| 4. 패트로누스 수련 | **연속 3회 성공** 필요(§3 연속 도전형). 실패 시 진행도 리셋 |
| 5. 수호신 완성 | 두려움 선택에 따라 **수호신 형태가 달라짐** → 도감 등재 |

> 이 체인 하나가 §2(기억) · §3(다단계) · 원작 활용을 전부 시연합니다. **첫 번째로 구현할 것을 권장.**

#### ② 도비
경고 → 무시/경청 → (경청 시) 위기에서 구해줌 → 양말 선물 → 자유 → 결전 참전

#### ③ 프레드 & 조지 → 도둑 지도
장난 상품 시식 참가 → 신뢰 획득 → **도둑 지도 증정** → 이동 시스템 강화(§11-6) → 비밀 통로 이벤트

#### ④ 소망의 거울 (에리세드)
심야 배회 중 발견 → **거울에 무엇이 보이는가 선택**(가족/친구/영광/평범한 나) → `memory` 기록 → 덤블도어의 대사 → **엔딩 텍스트에 반영**
> 선물용 게임에서 가장 감정적으로 남을 이벤트. 정성껏 쓸 것.

#### ⑤ 말포이 라이벌 관계
복도 시비 → 갈등 누적(`rivalry`) → 결투 클럽에서 정식 대결 → 승패가 이후 평판/이벤트에 반영

#### ⑥ 히포그리프 버클비크
해그리드의 수업 → **정중히 인사 판정** → 성공 시 비행 → 이후 위기에서 도움

#### ⑦ 필치 & 노리스 부인
통금 적발(누적) → 벌칙(금지된 숲 야간 탐험) → 켄타우로스/유니콘 조우 → 도둑 지도 있으면 회피 가능

#### ⑧ 폴리주스 마법약
재료 3종 수집(§3 수집형: 숲/상점/금서구역) → 조제 판정 → 성공 시 **잠입 이벤트** 해금

### 12-4. 따뜻하고 귀여운 단발 이벤트 (실패 페널티 없음)

§5에서 제안한 것에 원작 요소를 더 붙입니다.

| 이벤트 | 내용 |
|---|---|
| 헤드위그 | 부엉이장에서 쓰다듬기, 편지 배달 |
| 크룩섕스 | 도서관에서 무릎 위에 잠듦 → 잠시 공부 효율 상승 |
| 맨드레이크 분갈이 | 귀마개 필수! 깜빡하면 코믹한 실신 |
| 니어리 헤들리스 닉 | 데스데이 파티 초대 |
| 뚱뚱한 귀부인 | 암호를 잊어 초상화 앞에서 실랑이 |
| 초콜릿 개구리 카드 | 수집 요소 — 도감에 카드 등재 |
| 마법사의 체스 | 론과 한 판 |
| 첫 비행 수업 | 마담 후치, 빗자루 소환 판정 |
| 트릴로니 점괘 | 황당한 예언 — 아주 가끔 진짜로 적중 |
| 스프라우트 온실 | 식물에게 말 걸기 |
| 폭스(불사조) | 교장실에서 만남, 눈물의 치유 |

### 12-5. 규모 목표

**개수 목표를 세우지 않습니다.** 대신:

- 체인 **8개** (노드 합계 30~35)
- 귀여운 단발 **10~12개**
- 기존 42개 중 **최소 10개**에 `memory` 또는 `recall`을 소급 부여해 망에 편입

> 결과적으로 이벤트는 80여 개가 되지만, **중요한 건 그중 절반이 서로 연결된다는 점**입니다.

**영향 파일**: `js/data/events.js`(분할 검토), `js/data/chains.js`(신규), `js/systems/memory.js`, `js/systems/npc.js`(신규)

## 14. 앞서 "하지 말자"고 했던 것 중 하나를 뒤집습니다

§9에서 **"시간표(오전/오후/야간) 도입 ❌"** 라고 했었습니다. 그런데 이동 개편 요청이 들어오면서 조건이 바뀌어, **가벼운 형태로는 다시 제안할 만하다**고 판단했습니다. 입장을 바꾼 이유를 밝힙니다.

- 제가 반대했던 건 **"3개 슬롯에 활동을 배정하는 스케줄링 미니게임"** (Phase 5 원안)입니다. 이건 마감과 역할이 겹쳐서 여전히 반대합니다.
- 지금 제안하는 건 **"행동하면 때가 흘러가고, 때에 따라 같은 장소가 달라지는 것"** 뿐입니다. 배정도 계획도 없습니다.
- 이게 필요해진 이유: **같은 장소를 다시 가는 게 지루하다**는 문제를 가장 싸게 푸는 방법이기 때문입니다. 밤의 도서관과 낮의 도서관이 다르면, 장소 12개가 24개처럼 느껴집니다.
- 통금·필치·금서구역 잠입 같은 원작 소재가 **밤이 있어야 성립**합니다.

**결정 필요**: 이 가벼운 버전을 넣을지 말지. 넣는다면 §11(이동)과 같이 구현하는 게 효율적입니다.

## 15. 문장 — 이 게임의 가장 큰 결함 ⭐⭐

> 지적: *"소설처럼 상황묘사가 풍부해야 할 것 같아. 한두 줄짜리 대사와 상황묘사는 흥미를 이끌지 못해. 갑자기 누가 튀어나왔다. 이게 뭐야."*

### 15-1. 실측 결과

이벤트 본문 124개를 전수 조사했습니다.

| 지표 | 값 |
|---|---|
| 본문 길이 **중앙값** | **27자** |
| 40자 미만(한두 줄) 본문 | **102개 / 124개 (82%)** |
| 가장 짧은 본문 | **8자** |

**텍스트 게임인데 텍스트가 없습니다.** 시스템(판정·기억·파밍)을 아무리 쌓아도, 플레이어가 실제로 마주하는 건 저 27자입니다. 지금까지 만든 모든 기능보다 이게 우선입니다.

### 15-2. 왜 실패하는가 — 실제 사례 해부

```
'누군가 풀어놓은 콘월 픽시가 소란을 피운다!'
```

- **감각이 없다** — 안 들리고, 안 보이고, 냄새도 없다
- **요약이지 묘사가 아니다** — "소란을 피운다"는 상황 설명이지 장면이 아니다
- **정체를 먼저 말해버린다** — "픽시"라고 알려주고 시작하니 발견의 순간이 없다
- **주인공이 없다** — 영운이 뭘 느꼈는지 한 글자도 없다
- **위협이 안 선다** — 그래서 다음 화면의 전투가 뜬금없다

사용자 표현대로 **"갑자기 누가 튀어나왔다"** 가 정확한 진단입니다.

### 15-3. 문체 사양 (모든 신규·수정 텍스트가 지킬 것)

**① 3박자 구조: 감각 → 인지 → 반응**

| 박자 | 역할 |
|---|---|
| **감각** | 소리·빛·냄새·촉감으로 시작. *무엇인지 모른 채* 먼저 느낀다 |
| **인지** | 정체가 드러난다. 고유명사는 **여기서** 처음 등장 |
| **반응** | 영운의 신체 반응이나 짧은 내면. 선택 직전의 감정을 만든다 |

**② 분량 기준**

| 종류 | 분량 |
|---|---|
| 전투 진입 · 대형 이벤트 · 체인 노드 | **5~8문장** |
| 일반 조우 | 4~6문장 |
| 잡 이벤트 | 3~4문장 |
| **판정 결과(성공/실패)** | **최소 2~3문장** (지금은 대부분 1문장) |

**③ 금지**

- ❌ `갑자기`, `~가 나타났다!`, `~가 소란을 피운다` 같은 **요약형 서술**
- ❌ 첫 문장에 고유명사 노출 (`콘월 픽시가...` → 묘사 먼저, 이름은 나중에)
- ❌ 느낌표 남발 (한 이벤트에 1개 이하)
- ❌ **본문 안에 수치 표기** (`(지식 +2, 경험치 +12)`) — §15-5에서 시스템이 처리

**④ 시제·인칭**

3인칭 제한 시점(영운의 감각만). **과거형 기반**, 눈앞에서 벌어지는 동작은 현재형 허용 — 한국어 소설의 자연스러운 혼용을 따른다.

**⑤ 상태 반영 (여력 되면)**

같은 이벤트라도 조건에 따라 첫 문장을 바꿀 수 있게 한다. 밤/체력 위험/기억 보유 여부에 따라 다른 도입부 → 재방문이 지루하지 않다.

### 15-4. 개작 예시 (Before / After)

#### ① 전투 진입 — 콘월 픽시

**Before** (24자)
> 누군가 풀어놓은 콘월 픽시가 소란을 피운다!

**After**
> 복도 저편에서 유리 깨지는 소리가 났다.
>
> 모퉁이를 돌자 새파란 것이 눈앞을 스쳐 지나간다. 깃털인가 싶었지만 아니었다. 잠자리 날개를 단 손바닥만 한 것들이 천장 밑을 맴돌며 촛대를 흔들어대고 있다.
>
> 그중 하나가 문득 동작을 멈추더니, 고개를 꺾어 영운을 내려다본다. 얄팍한 입꼬리가 천천히 올라갔다.
>
> 누가 장난삼아 우리를 열어둔 모양이다. 콘월 픽시 — 그것도 한둘이 아니다.
>
> 지팡이를 쥔 손에 저절로 힘이 들어갔다.

> 핵심: **소리 → 오인 → 정정 → 저쪽이 나를 발견 → 명명 → 신체 반응.** "저쪽이 나를 알아본다"는 박자가 위협을 만듭니다.

#### ② 잡 이벤트 — 갈레온 줍기 (사소한 것도 살릴 수 있다)

**Before** (25자)
> 복도 구석에서 반짝이는 갈레온 몇 개를 발견했다.

**After**
> 갑옷 받침대 아래, 먼지 사이로 무언가 반짝였다.
>
> 쭈그려 앉아 손을 뻗으니 차가운 금속이 손끝에 닿는다. 갈레온 세 닢. 가장자리가 닳고 거뭇해진 걸 보면 꽤 오래 이 자리에 있었던 모양이다.
>
> 누가 흘렸을까. 아니면, 잊어버린 걸까.
>
> 영운은 복도를 한 번 둘러보았다. 인기척은 없다.

#### ③ 판정 결과 — 피브스의 물풍선

**Before** — 대성공 / 실패
> 가볍게 피하며 멋진 몸놀림을 보였다. (민첩 +1)
> 물풍선을 정통으로 맞았다. 로브가 흠뻑 젖었다.

**After** — 대성공
> 물풍선이 손을 떠나는 순간, 영운은 이미 반 발짝 옆으로 몸을 틀고 있었다.
>
> 풍선은 등 뒤 벽에 부딪혀 요란하게 터졌다. 물방울 하나 튀지 않았다.
>
> 피브스가 입을 벌린 채 공중에 멈춰 있다. 재미없다는 듯 혀를 차더니 천장을 뚫고 사라졌다.

**After** — 실패
> 피하려고 몸을 틀었지만 한 박자 늦었다.
>
> 차가운 물이 정수리부터 쏟아져 어깨를 타고 흘러내린다. 로브가 순식간에 무거워졌다.
>
> 피브스가 배를 잡고 공중을 데굴데굴 구른다. 그 웃음소리가 복도 끝까지 울렸다.

#### ④ 따뜻한 이벤트 — 크룩섕스 (신규, 선물용 톤 견본)

> 도서관 창가 자리. 세 번째 문단을 두 번째로 다시 읽던 참이었다.
>
> 무릎이 묵직해진 걸 깨달은 건 그때였다. 언제 올라왔는지도 모를 주황색 덩어리 하나가 다리 위에 자리를 잡고 있다. 납작한 얼굴에 병솔 같은 꼬리 — 헤르미온느의 고양이, 크룩섕스다.
>
> 비켜달라고 손을 대자 녀석이 눈을 반쯤 떴다. 영운을 한 번 올려다보고는, 다시 감는다.
>
> 안 비킬 모양이다.
>
> 창으로 오후 햇살이 길게 들어왔다. 무릎이 따뜻했다.

### 15-5. 함께 고쳐야 할 구조 — 수치를 본문에서 분리

현재 작가가 본문 안에 수치를 손으로 적고 있습니다.

```js
text: '남작이 감탄하며 사라진다. (지식 +2, 경험치 +12)'   // ❌ 몰입 파괴 + 오타 위험
```

`effect` 객체에서 **자동 생성**해 별도 스타일로 렌더링해야 합니다.

```
남작이 흡족한 듯 고개를 끄덕였다. 그러고는 벽 속으로
스르르 몸을 감추었다.

  ┌ 지식 +2 · 경험치 +12 ┐          ← 시스템 영역(별도 색·작은 글씨)
```

효과: 몰입 유지 · 표기 누락/오타 방지 · 작가는 문장에만 집중.

### 15-6. 타자 효과와의 시너지

지금 타자 효과가 밋밋한 이유 중 하나가 **칠 글자가 27자밖에 없어서**입니다. 긴 문장이 들어오면 타자 효과가 비로소 제 역할을 합니다. 단, 두 가지를 함께 손봐야 합니다.

- **문단 단위 출력** — 긴 본문을 한 덩어리로 쏟지 말고, 빈 줄 기준으로 끊어서 **문단 사이에 짧은 호흡**을 둔다
- **속도 재조정** — 문단이 길어지므로 현재 22ms/자는 답답할 수 있음. 시각 확인 후 조정
- (이미 요청하신) **화면 아무 데나 탭 → 전체 즉시 출력**

### 15-7. 작업 순서 — 124개를 한 번에 고칠 수는 없다

플레이어가 **가장 집중하는 순간**부터 고칩니다.

| 순위 | 대상 | 개수(약) | 이유 |
|:---:|---|---:|---|
| **1** | 전투 진입 텍스트 | 12 | 가장 긴장되는 순간인데 지금 한 줄짜리 |
| **2** | 대형 이벤트 · 체인 노드 | 30+ | 서사의 뼈대. 신규 작성이므로 처음부터 사양대로 |

| **4** | 판정 결과(성공/실패) | 60+ | 4단계 결과의 차이를 문장으로 체감시킴 |
