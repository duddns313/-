# 밸런스 시뮬레이션 리포트

`scripts/simulate.js`로 헤드리스 브라우저에서 실제 게임 코드를 그대로 실행해, 휴리스틱 AI로
자동 플레이한 결과를 정리한 문서입니다. (Phase 7~9 구현 직후 실시)

## 방법

- 실제 `index.html`을 정적 서버로 띄우고 Playwright 헤드리스 크로미움에서 로드
- 4개 기숙사를 순환하며 각 회차 새 캐릭터 생성
- 휴리스틱 AI: 체력 낮으면 회복→도주, 전투는 가장 강한 시전 가능 공격 주문 사용, 상점에서 물약·장비·마법석·주문서를 우선순위대로 구매, 미확인 장비 자동 감정·교체·강화, 스토리 조건 충족 시 최우선으로 진행
- 회차당 최대 900회 행동, 24회 반복

## 과정에서 발견하고 수정한 것

### 1. 치명적 버그 — 비밀의 방으로 가는 길이 없었다 (심각도: 최상)

`corridors` 장소의 `connections` 배열에 `chamberOfSecrets`가 빠져 있었습니다. 2장을 완료해
`chamber_unlocked` 플래그가 켜져도, 어떤 장소의 이동 버튼에도 "비밀의 방"이 노출되지 않아
**실제 플레이어는 메인 스토리를 끝까지 진행할 방법이 전혀 없었습니다.** 지금까지의 모든
Playwright 테스트가 `travelTo('chamberOfSecrets')`를 코드로 직접 호출해 검증했기 때문에
이 문제를 놓치고 있었습니다 — 실제 UI 버튼을 클릭하는 시뮬레이터를 돌리고 나서야 드러났습니다.

**조치**: `js/data/locations.js`의 `corridors.connections`에 `'chamberOfSecrets'`를 추가.
실제 버튼 클릭으로 재검증 완료.

### 2. 전투 난이도가 사실상 존재하지 않았다 (심각도: 상)

1차 배치(24회, 보스 능력치 원본 기준)에서:

| 지표 | 값 |
|---|---|
| 완결률 | 24/24 (100%) |
| **전투 패배 횟수** | **0/24 — 단 한 번도 없음** |
| 톰 리들 환영 처치율 | 100% |
| 볼드모트 잔영 처치율(클리어율) | 100% |
| 평균 습득 주문 수 | 2.1개 (시작 주문 2개 그대로에 가까움) |

주문을 거의 배우지 않고 기본 주문(익스펠리아무스)만으로 밀어붙이는 플레이로도 보스전을
포함해 단 한 번도 패배하지 않았습니다. 원인은 플레이어 능력치(레벨당 공격력·방어력 고정
증가 + 장비 보너스)는 계속 우상향하는 반면, 적 능력치는 완전히 고정값이라 스토리를 예상보다
빠르게 진행하면 손쉽게 적정 레벨을 앞지르기 때문입니다. 이 상태로는 "최종 결전"이라는
이름에 걸맞은 긴장감이 전혀 없었습니다.

**조치**: 3대 보스(톰 리들의 환영·바실리스크·볼드모트의 잔영)의 공격력·방어력·체력을
20~30% 상향.

| 적 | 이전 (HP/ATK/DEF) | 이후 |
|---|---|---|
| 톰 리들의 환영 | 100 / 20 / 8 | 115 / 26 / 10 |
| 바실리스크 | 140 / 24 / 10 | 150 / 28 / 12 |
| 볼드모트의 잔영 | 180 / 28 / 11 | 195 / 36 / 15 |

재검증(24회):

| 지표 | 이전 | 이후 |
|---|---|---|
| 완결률 | 100% | 96% (23/24) |
| 전투 패배 | 0 | 1건 발생 (최종 보스에게 패배 → "쓰러진 자" 엔딩 진입 확인) |
| 클리어율 | 100% | 96% |

여전히 대부분 클리어 가능하면서도 실제로 질 수 있는 긴장감이 생겼습니다. 준비가 부족한
플레이(스크롤·수업을 거의 이용하지 않고 밀어붙이는 플레이)에는 최종 보스가 실제 위협이
되도록 만든 것으로, "주문/장비를 준비해야 한다"는 시스템의 존재 이유를 살립니다.

### 3. 엔딩 분포 쏠림 (심각도: 하 — 조치 보류)

24회 모두 `balanced`(22) / `light`(1) 엔딩에 몰렸고 `dark`, `together` 엔딩은 관측되지
않았습니다. 다만 이는 휴리스틱 AI가 "표시된 성공률이 가장 높은 선택지"만 기계적으로 고르고
성향을 의도적으로 극단으로 몰지 않기 때문일 가능성이 큽니다 — 실제로 다크 주문을 일부러
연발하거나 동료와 적극적으로 교류하는 플레이어라면 다른 결과가 나올 것입니다. 수치를 임의로
바꾸기보다, 실제 플레이 데이터(또는 사람이 의도적으로 각 루트를 타는 테스트)로 다시 확인한
뒤 조정하는 것을 권장하며 이번에는 손대지 않았습니다.

### 4. 그 외 관측 (참고용, 조치 없음)

- 평균 완결 소요일 108일, 평균 최종 레벨 9.5 — 1~3학년 완결 스코프에 무리 없는 페이스
- 장비 등급 분포(common 209 · uncommon 92 · rare 43 · epic 15 · legendary 8, 24회 합산)는
  건전한 피라미드 형태로 특별한 문제 없음
- 평균 업적 9.1/22 — 절반에 조금 못 미치는 수준으로, 한 회차에 다 모으긴 어렵고 새 게임+의
  동기가 되는 정도로 적절해 보임

## 시뮬레이터 자체의 한계 (참고)

- 완전히 합리적인 최적 플레이가 아니라 단순 휴리스틱입니다. 최적 플레이보다 스토리를
  약간 늦게 진행하고, 동료 호감도 상승에 소극적입니다.
- 판정 있는 선택지에서 "표시된 성공률"만 보고 고르며, 성향/역할극 의도는 반영하지 않습니다.
- 이런 한계 때문에 절대적인 수치(정확히 며칠, 정확히 몇 레벨)보다는 **상대적 신호**(0번의
  패배처럼 "0"이나 "100%" 같은 극단값)에 더 신뢰를 둬야 합니다. 이번 리포트의 조치들도
  전부 그런 극단값 신호에 기반했습니다.

## 재현 방법

```
node scripts/simulate.js [실행횟수] [행동상한]
# 예: node scripts/simulate.js 24 900
```
원본 데이터는 `scripts/simulation_raw.json`에 저장됩니다 (git에는 커밋하지 않음, 실행할 때마다 갱신).
