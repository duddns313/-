## 0. 현재 상태 진단

| 항목 | 현재 | 문제점 |
|---|---|---|
| 코드 규모 | 1,509줄 (js 920줄) | 관리 가능하나 확장 시 engine.js 비대화 |

## 1. 능력 판정 시스템 (최우선 — 게임의 근간)

서울 2033·모험과 이야기의 정체성. **모든 의미 있는 선택지에 성공률을 부여**합니다.

### 1-1. 능력치 확장 (3종 → 5종)

| 능력치 | 담당 판정 |
|---|---|
| 지식(知) | 주문 시전, 수수께끼, 마법 이론, 금서 해독 |
| 용기(勇) | 위험 감수, 보스 대치, 도주 성공률 |
| 매력(魅) | 설득, NPC 호감, 상점 흥정, 교수 무마 |
| **민첩(敏)** *(신규)* | 회피, 잠입, 야간 이동 시 발각 회피 |
| **행운(運)** *(신규)* | 전 판정 소폭 보정, 희귀 이벤트·드랍 확률 |

### 1-2. 판정 공식

```js
// js/systems/check.js (신규)
function skillCheck(statKey, difficulty) {
  const stat = getStat(statKey);
  const BASE = 45;
  const rate = clamp(BASE + (stat - difficulty) * 4 + luckBonus(), 5, 95);
  const roll = randInt(1, 100);
  const critLine = Math.max(1, Math.floor(rate * 0.1));
  return {
    rate, roll,
    tier: roll <= critLine ? 'critical'   // 대성공
        : roll <= rate      ? 'success'   // 성공
        : roll > 96         ? 'fumble'    // 대실패
        :                     'fail'      // 실패
  };
}
```

- **4단계 결과**(대성공/성공/실패/대실패)로 기억에 남는 순간을 만듭니다.
- 난이도(difficulty)는 이벤트 데이터에 명시: `{ stat: 'intelligence', dc: 8 }`
- **성공률을 버튼에 미리 표시**합니다 → `[지식 판정 · 성공률 72%]`
  플레이어가 위험을 계산할 수 있어야 "선택"이 성립합니다.

### 1-3. 데이터 스키마 변경

```js
// 기존
{ label: '주문으로 쫓아낸다', effect: {...}, resultText: '...' }

// 변경 후
{
  label: '주문으로 쫓아낸다',
  check: { stat: 'intelligence', dc: 7 },
  outcomes: {
    critical: { effect: { exp: 12, courage: 2 }, text: '완벽한 시전! ...' },
    success:  { effect: { exp: 6 },              text: '피브스가 도망간다.' },
    fail:     { effect: { hp: -5 },              text: '주문이 빗나갔다.' },
    fumble:   { effect: { hp: -12, alignment: -2 }, text: '주문이 역류했다!' }
  }
}
```

> **하위 호환**: `check`가 없는 선택지는 기존처럼 무조건 성공 처리 → 기존 이벤트를 한 번에 고칠 필요 없이 점진적 마이그레이션 가능.

### 1-4. 판정 연출 (UI 연동)

주사위 굴림 애니메이션 → 숫자 카운트업 → 성공/실패 색상 플래시 → 결과 텍스트.
`navigator.vibrate()`로 대성공/대실패 시 햅틱 피드백(모바일 체감 큼).

**영향 파일**: `js/systems/check.js`(신규), `js/data.js`, `js/engine.js`, `js/ui.js`

## 2. 자원·시간 관리 (서울 2033 차용)

현재 "탐험" 버튼을 무한히 누를 수 있어 **기회비용이 존재하지 않습니다.** 이것이 게임을 단조롭게 만드는 근본 원인입니다.

### 2-1. 기력(Stamina)

- 최대 100. 탐험 15, 수련 20, 전투 10, 이동 5 소모
- 0이 되면 강제 휴식(하루 소모 + 패널티)
- 휴식·음식·물약으로 회복
- → **"오늘 무엇을 할 것인가"** 라는 결정이 비로소 발생

### 2-2. 시간표 시스템

하루 = **오전 / 오후 / 야간** 3슬롯.

| 슬롯 | 특성 |
|---|---|
| 오전 | 수업(학업 상승, 신규 주문 습득 조건) |
| 오후 | 자유 활동 — 탐험, 상점, 친구 교류 |
| 야간 | **고위험 고보상** 탐험. 단, 발각 판정(민첩) 실패 시 벌점·기숙사 점수 차감 |

### 2-3. 신규 지표

- **학업 성취도**: 수업 참석 시 상승, 결석 시 하락. 일정 이하 → 퇴학 경고 루트
- **기숙사 점수**: 선행·수업·퀘스트로 획득, 규칙 위반 시 차감
  → **기숙사 우승컵**이라는 장기 목표 (목표설정이론의 핵심 장치)

> **설계 의도**: 모범생 루트 ↔ 모험가 루트의 긴장. 밤에 몰래 나가 강해질 것인가, 수업을 지켜 안정적으로 클리어할 것인가. 이것이 이 게임 고유의 정체성이 됩니다.

**영향 파일**: `js/state.js`, `js/systems/time.js`(신규), `js/engine.js`, `js/ui.js`

## 3. 전투 심화

현재는 "가장 센 주문 연타"가 최적해입니다. 전술적 선택지를 부여합니다.

| 요소 | 내용 |
|---|---|
| **태세** | 공격 / 방어 / 집중(마력 회복, 다음 턴 위력 증가) 3각 구도 |
| **상태이상** | 기절, 마비, 화상, 공포(디멘터·명중률 저하), 무장해제(주문 사용 불가) |
| **시전 판정** | 고위력 주문일수록 지식 판정 필요 → 실패 시 마력만 소모. 판정 시스템과 연결 |
| **약점 속성** | 적별 약점 주문 일반화 (현재 패트로누스-디멘터만 존재) |
| **보스 패턴 예고** | "볼드모트가 지팡이를 치켜든다 — **다음 턴 강공격!**" → 플레이어가 프로테고 선택 |
| **연계** | 스투페파이(기절) 후 공격 시 피해 증가 |

> 보스 패턴 예고는 **가장 비용 대비 효과가 큰 전투 개선**입니다. 정보를 주고 대응을 요구하는 것만으로 전투가 퍼즐이 됩니다.

**영향 파일**: `js/systems/combat.js`(engine.js에서 분리), `js/data.js`

## 4. 성취·동기 설계 (게임화 이론 적용)

### 4-1. 이론적 근거

| 이론 | 적용 |
|---|---|
| **자기결정이론(SDT)** | 자율성 = 다중 루트·엔딩 / 유능감 = 난이도 곡선·명확한 피드백 / 관계성 = 동료 시스템(6장) |
| **목표설정이론(Locke & Latham)** | 구체적·도전적 목표 + 즉각 피드백 → 일일 과제 / 학년 목표 / 기숙사 우승컵 |
| **몰입(Flow)** | 지역별 권장 레벨 표시, 난이도 자동 보정으로 실력-난이도 균형 유지 |
| **가변비율 보상** | 희귀 이벤트, 확률 드랍 테이블 → 탐험 반복 동기 |
| **Octalysis** | 소유(수집) · 희소성(한정 이벤트) · 사회적 영향(기숙사 경쟁) · 미지(랜덤) |

### 4-2. 구현 기능

- **업적 30~50종**: 첫 승리 / 무피해 보스 격파 / 전 주문 습득 / 완전한 어둠 / 7년 개근 등
  → 각 업적에 **소량의 영구 보너스** 부여 → 회차 플레이 동기
- **도감(Codex)**: 마법 생물·주문·아이템 도감. 조우/습득 시 해금, 완성률 표시
  → 수집 욕구는 텍스트 게임에서 가장 저렴하고 강력한 리텐션 장치
- **칭호**: 조건 달성 시 획득, 장착 시 소폭 버프 (자기표현 + 유능감)
- **일일 과제**: "탐험 3회", "수업 참석", "친구와 대화" → 세션 단위 목표
- **7학년 구조**: 현재 4챕터 → 1~7학년 각 1개 메인 챕터. 명확한 장기 로드맵
- **New Game+**: 클리어 시 업적 보너스·도감 계승, 난이도 상승

**영향 파일**: `js/systems/achievement.js`, `js/systems/codex.js`(신규), `data/achievements.json`

## 5. 모바일 우선 UI/UX

> 사용자가 실제로 폰에서 플레이하므로 **모바일이 기본, 데스크톱이 확장**입니다.

### 5-1. 구조 개편

- **하단 탭 네비게이션**: `[모험] [캐릭터] [소지품] [도감] [기록]`
  현재 사이드바에 모든 정보가 세로로 쌓여 스크롤이 길어지는 문제 해결
- **부분 렌더링**: 현재 `render()` 전체 재구성(29곳)을 영역별 갱신으로 전환
  → 스크롤 위치 유지, 애니메이션 가능, 입력 포커스 보존
- **상단 고정 상태바**: 체력·기력·마력·날짜만 항상 노출

### 5-2. 연출·피드백

- **타이프라이터 텍스트** + 탭하면 즉시 완료 (텍스트 게임 몰입의 핵심)
- **토스트/스낵바**: 레벨업·업적 획득 (현재 `alert()` 대체)
- **바텀시트 모달**: 아이템 상세, 확인 대화상자 (`confirm()` 대체)
- **전투 HUD**: 데미지 숫자 팝업, 체력바 감소 애니메이션, 상태이상 아이콘
- **햅틱**: 판정 성공/실패, 피격 시 `navigator.vibrate()`

### 5-3. 접근성·편의

- 최소 44×44px 탭 타겟, 폰트 크기 조절(3단계)
- `prefers-reduced-motion` 대응, 명암비 WCAG AA 확보
- **가로/세로 모두 대응**, safe-area(노치) 대응

### 5-4. PWA 전환 ⭐

`manifest.json` + service worker 추가 →
**홈 화면에 앱으로 설치, 오프라인 플레이 가능.**
현재 폰으로 플레이하는 상황에서 **체감 개선이 가장 큰 항목**입니다.

**영향 파일**: `index.html`, `css/style.css`, `js/ui.js`(모듈 분리), `manifest.json`·`sw.js`(신규)

## 7. 기술 기반 개선 (선행 필수)

| 항목 | 내용 | 이유 |
|---|---|---|
| **세이브 버전·마이그레이션** | `saveVersion` 필드 + 마이그레이션 함수 | **이걸 먼저 안 하면 이후 모든 구조 변경이 기존 세이브를 파손** |

| **다중 슬롯** | 3슬롯 + 슬롯별 요약 표시 | |
| **콘텐츠 JSON 분리** | 이벤트·스토리를 `data/*.json`으로 | 이벤트 150개 확장 시 코드 수정 없이 추가 가능 |
| **모듈 분리** | engine.js → combat/explore/story/economy | 현재 461줄, 계획대로면 1,500줄 이상 예상 |
| **시드 RNG** | 재현 가능한 난수 | 버그 재현·밸런스 테스트에 필수 |
| **밸런스 시뮬레이터** | 자동 플레이 1,000회로 승률·성장곡선 검증 | 수동 테스트로는 밸런싱 불가능 |

| **4** | 전투 심화 (태세·상태이상·보스 패턴) | |
| **5** | 업적·도감·칭호·일일 과제 | 리텐션 장치 |
| **6** | 동료 관계 + 7학년 서사 + 엔딩 확장 | |
| **7** | 콘텐츠 대량 투입 + 밸런스 시뮬레이션 | 시스템 확정 후 투입해야 재작업 없음 |

> **최소 실행 권장(Phase 0→1→2)**: 이 셋만 완료해도 "판정이 있는 제대로 된 모바일 텍스트 RPG"가 됩니다.

## 10. 결정이 필요한 사항

구현 전 확정해두면 좋은 설계 분기입니다.

1. **게임 구조**: 연속 캠페인형(현재) vs 로그라이트 회차형(사망 시 리셋, 영구 성장 계승)
   → **권장: 캠페인 + New Game+**. 서울 2033의 긴장감을 원하면 "어려움" 난이도에서만 퍼머데스 적용하는 절충안도 가능.
2. **분량 vs 완성도**: 7학년 전체 구현 vs 1~3학년 완성 후 확장
   → **권장: 1~3학년 먼저 완성.** 미완성 7학년보다 완결된 3학년이 낫습니다.
3. **이벤트 작성 방식**: 직접 집필 vs 템플릿 기반 조합 생성
   → **권장: 핵심 스토리는 집필, 잡다한 조우는 템플릿 조합.**
