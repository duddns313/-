# 호그와트: 그림자의 잔영 — 업그레이드 계획서 (v2)

> 이 문서는 구현 지침서입니다. 각 Phase는 독립적으로 완료·배포 가능하도록 설계했습니다.
> 참고 게임: **서울 2033**(자원·턴 관리, 능력 판정), **모험과 이야기**(선택지 판정, 성장·수집)

## 구현 현황 (Phase 0~4 완료)

Phase 0~4가 구현되어 브랜치에 반영되었습니다. Playwright로 캐릭터 생성부터 최종 보스·엔딩까지 전 구간을 자동 클릭 테스트했고, 모바일 뷰포트(390×844)에서 탭 전환·바텀시트·토스트·판정 연출까지 시각 확인을 마쳤습니다.

- **구조 변경**: `js/data.js` 단일 파일을 `js/data/*.js`(houses/rarity/spells/enemies/locations/events/story/endings) + `js/systems/*.js`(check/item/loot/spell)로 분리. `index.html`의 `<script>` 순서로 로드하며 fetch/CORS 문제없이 `file://`에서도 동작.
- **세이브**: `saveVersion` 필드 도입(`hp_text_game_save_v2`). 이번 리팩터링은 인벤토리·주문·능력치 구조 자체가 바뀌어 v1 세이브는 안전 이관이 불가능했기에 **호환 불가 처리(정리 후 새 시작 안내)** 로 마무리하고, v2부터는 버전 비교 기반 이관 골격을 갖춤.
- **부분 렌더링**: 로그는 `uiAppendLogEntry`로 append-only(전체 재구성 제거), 나머지 패널은 활성 탭만 갱신.
- **PWA**: `manifest.json` + `sw.js`(cache-first) + 자체 생성 아이콘(192/512). 홈 화면 설치·오프라인 실행 가능.
- **판정 시스템**: `js/systems/check.js`의 `skillCheck(stat, dc)` — 대성공/성공/실패/대실패 4단계, 성공률을 선택지 버튼에 사전 표시. 지식/용기/매력/민첩/행운 5스탯 전면 적용.
- **모바일 UI 셸**: 하단 탭(모험/캐릭터/소지품/도감/기록), 상단 고정 HP·MP 미니바, 타이프라이터 로그(탭하여 스킵), 토스트(`alert()` 대체), 바텀시트(`confirm()`·아이템 상세 대체), 판정 플래시+햅틱.
- **주문 시스템**: 레벨업 자동 습득 완전 제거. 수업 진도/주문서/사사(대사 크리티컬)/금서/보스드랍 5경로 구현. 숙련도 0~100 4단계(미숙/능숙/숙달/통달), 선행조건, 레벨 기반 슬롯 제한(문서의 "학년" 대신 레벨을 게이트로 사용 — 3학년 서사 구조 자체는 Phase 8 범위라 별도 확정 필요), 주문 잊기(재설계) 지원.
- **아이템 시스템**: 6등급 희귀도 + 접두/접미 접사, 미확인 드랍 → 지식 판정 감정, 강화 +0~10(+4까지 100%, 실패 시 등급 하락), 지팡이 뽑기(재료 궁합 시 보너스 접사). 세트 아이템·저주받은 아이템·마법약 조제는 우선순위상 이번 범위에서 제외(중요도 "중", 후속 과제로 남김).

**다음 결정 필요 사항**: Phase 5(자원·시간표) 진행 여부, 그리고 위에서 레벨 게이트로 대체한 "학년" 개념을 Phase 8에서 어떻게 도입할지.

## 확정 사항

- **범위: 1~3학년으로 완결.** 7학년 구조는 폐기. 3학년 종료 시 완결된 엔딩 제공.
- **밸런스 시뮬레이터는 구현 담당(소넷)이 직접 작성·실행**한다. (Phase 7)
- **주문·아이템 자동 습득 폐지.** 모든 획득은 플레이어의 행동·선택·운의 결과여야 한다.

## 1. 능력 판정 시스템 (최우선 — 게임의 근간)

### 1-1. 능력치 확장 (3종 → 5종)

| 능력치 | 담당 판정 |
|---|---|
| 지식(知) | 주문 시전·습득, 수수께끼, **아이템 감정**, 금서 해독 |
| 용기(勇) | 위험 감수, 보스 대치, 도주 |
| 매력(魅) | 설득, NPC 호감, 흥정, 교수 무마 |
| **민첩(敏)** *(신규)* | 회피, 잠입, 야간 이동 시 발각 회피 |
| **행운(運)** *(신규)* | 전 판정 보정, **희귀 드랍·강화 성공률** |

### 1-2. 판정 공식

```js
// js/systems/check.js (신규)
function skillCheck(statKey, difficulty) {
  const stat = getStat(statKey);
  const BASE = 45;
  const rate = clamp(BASE + (stat - difficulty) * 4 + luckBonus(), 5, 95);
  const roll = randInt(1, 100);
  const critLine = Math.max(1, Math.floor(rate * 0.1));
  return {
    rate, roll,
    tier: roll <= critLine ? 'critical'   // 대성공
        : roll <= rate      ? 'success'   // 성공
        : roll > 96         ? 'fumble'    // 대실패
        :                     'fail'      // 실패
  };
}
```

- **4단계 결과**로 기억에 남는 순간을 만든다.
- **성공률을 버튼에 미리 표시** → `[지식 판정 · 성공률 72%]`
  위험을 계산할 수 있어야 "선택"이 성립한다.
- 난이도는 데이터에 명시: `{ stat: 'intelligence', dc: 8 }`

### 1-3. 데이터 스키마

```js
{
  label: '주문으로 쫓아낸다',
  check: { stat: 'intelligence', dc: 7 },
  outcomes: {
    critical: { effect: { exp: 12, courage: 2 }, text: '완벽한 시전! ...' },
    success:  { effect: { exp: 6 },              text: '피브스가 도망간다.' },
    fail:     { effect: { hp: -5 },              text: '주문이 빗나갔다.' },
    fumble:   { effect: { hp: -12, alignment: -2 }, text: '주문이 역류했다!' }
  }
}
```

> **하위 호환**: `check`가 없는 선택지는 기존처럼 무조건 성공 → 점진적 마이그레이션 가능.

**영향 파일**: `js/systems/check.js`(신규), `js/data.js`, `js/engine.js`, `js/ui.js`

## 2. 주문 습득·성장 시스템 ⭐ (자동 습득 전면 폐지)

**현재 `checkSpellUnlocks()`를 완전히 제거한다.** 레벨업만으로 주문을 얻으면 획득의 쾌감이 없다.

### 2-1. 습득 경로 5종

| 경로 | 방식 | 설계 의도 |
|---|---|---|
| **① 수업 수강** | 오전 수업 슬롯에서 과목 수강 → **학습 진도** 누적, 100% 도달 시 습득. 지식 능력치가 높을수록 진도 획득량 증가 | 시간표 시스템과 직결. 기본 주문의 주 획득처 |
| **② 주문서(스크롤)** | 드랍·상점·퀘스트 보상. 사용 시 **지식 판정** → 성공 시 습득, 실패 시 스크롤 소모 | 파밍 동기. 희귀 주문은 스크롤로만 습득 |
| **③ 교수 사사** | 특정 교수 호감도 임계값 도달 → 전용 주문 전수 | 관계 시스템과 연결. 노력의 보상 |
| **④ 금서 구역 해독** | 어둠의 주문 전용. **성향 하락**을 대가로 지불 | 섹텀셈프라·아바다 케다브라는 오직 이 경로. 대가가 있는 힘 |
| **⑤ 보스 드랍** | 보스 처치 시 고유 주문서 확정 드랍 | 도전의 보상 |

과목: 마법주문학 / 어둠의마법방어술 / 변신술 / 마법약 / 약초학

### 2-2. 주문 숙련도 (Mastery)

각 주문에 숙련도 0~100. **사용할 때마다 상승.**

| 구간 | 등급 | 효과 |
|---|---|---|
| 0–29 | 미숙 | 시전 실패 확률 존재 |
| 30–59 | 능숙 | 마력 소모 -10% |
| 60–89 | 숙달 | 위력 +20%, 마력 -20% |
| 90–100 | 통달 | 위력 +40%, 시전 실패 없음, 고유 추가효과 해금 |

> 애용하는 주문에 보상을 준다. "새 주문이 무조건 상위호환"인 구조를 깨서, 플레이어마다 다른 주력 주문이 생긴다.

### 2-3. 주문 계열 트리

5계열 — **공격 / 방어 / 변신 / 저주(어둠) / 치유·보조**

- 선행 조건 존재: *"익스펠리아무스 숙련 50 이상 → 스투페파이 습득 가능"*
- 학년당 습득 가능 슬롯 제한 → **전 계열 마스터 불가, 선택 강제**
- → 자동 지급이 아니라 **플레이어가 빌드를 설계**한다

**영향 파일**: `js/systems/spell.js`(신규), `js/data.js`, `data/spells.json`

## 3. 아이템 희귀도·파밍 시스템 ⭐

현재 아이템은 고정 성능이라 드랍이 무의미하다. 상용 RPG의 검증된 구조를 적극 도입한다.

### 3-1. 희귀도 6등급

| 등급 | 색상 | 랜덤 옵션 수 |
|---|---|---|
| 평범 (Common) | 회색 | 0 |
| 쓸만한 (Uncommon) | 초록 | 1 |
| 진귀한 (Rare) | 파랑 | 2 |
| 명품 (Epic) | 보라 | 3 |
| 전설 (Legendary) | 주황 | 4 + 고유 효과 |
| **성물 (Artifact)** | 금색 | 고정 고유 효과 (게임 내 유일, 퀘스트 전용) |

### 3-2. 랜덤 옵션 (접두/접미) — 가장 효율 높은 시스템

적은 아이템 종류로 **조합적 다양성**을 만든다.

- **접두사**: 날카로운(공격) / 견고한(방어) / 현자의(지식) / 신속한(민첩) / 행운의(행운)
- **접미사**: ~불사조의(체력 재생) / ~뱀의(어둠 주문 강화) / ~사자의(용기) / ~독수리의(마력)
- 표기 예: **`날카로운 지팡이 : 불사조의 가호`** (진귀한)
- 수치도 범위 내에서 롤 → 같은 아이템이라도 개체차 발생 → "완벽한 롤" 추구

### 3-3. 부가 시스템

| 시스템 | 내용 | 우선순위 |
|---|---|:---:|
| **아이템 감정** | 미감정 상태로 드랍 → **지식 판정**으로 감정, 실패 시 재시도. 개봉 전 긴장감 | 상 |
| **강화 (+0~+10)** | 마법석 소모. +4까지 100%, 이후 확률 하락. **실패 시 등급 하락(파괴 없음)** | 상 |
| **지팡이 뽑기** | 올리밴더에서 갈레온 소모, 랜덤 획득. *"지팡이가 마법사를 선택한다"* — **원작 설정을 가챠로 승화**. 재료(불사조깃털/용심장근/유니콘털) × 목재 조합, 내 성향·기숙사와 궁합 시 보너스 | **최상** |
| **세트 아이템** | 기숙사별 4부위(지팡이·로브·장신구·부적). 2세트 스탯 / 4세트 고유 능력 | 중 |
| **저주받은 아이템** | 강력하나 **해제 불가 + 성향 지속 하락**. 교수 도움이나 정화 의식으로만 해제 | 중 |
| **드랍 테이블** | 적 등급 × 지역 위험도로 희귀도 가중치 결정. **야간·금지된 숲에서 고등급 확률 상승** | 상 |
| **마법약 조제** | 약초학 채집 → 레시피 조합. 마법약 수업과 연결 | 중 |

> **지팡이 뽑기를 최우선 추천합니다.** 원작 고증("지팡이가 마법사를 선택한다")과 가챠의 게임성이 정확히 일치하는 드문 사례입니다. 도입 비용 대비 체감이 가장 큽니다.

> **내구도 시스템은 도입하지 않습니다.** 관리 부담만 늘고 재미를 주는 경우가 드뭅니다.

**영향 파일**: `js/systems/item.js`, `js/systems/loot.js`(신규), `data/affixes.json`

## 4. 자원·시간 관리 (서울 2033 차용)

현재 "탐험"을 무한히 누를 수 있어 **기회비용이 없다.** 이것이 단조로움의 근본 원인.

- **기력(Stamina)** 최대 100. 탐험 15 / 수련 20 / 전투 10 / 이동 5. 0이면 강제 휴식
- **시간표** — 하루 3슬롯

| 슬롯 | 특성 |
|---|---|
| 오전 | 수업 — 학업·**주문 학습 진도** 상승 |
| 오후 | 자유 — 탐험·상점·교류 |
| 야간 | **고위험 고보상** 탐험. **고등급 드랍률 상승.** 단 발각 판정(민첩) 실패 시 벌점 |

- **학업 성취도** — 결석 누적 시 퇴학 경고 루트
- **기숙사 점수** — **기숙사 우승컵**이라는 장기 목표 (목표설정이론의 핵심 장치)

> **설계 의도**: *"밤에 몰래 나가 좋은 아이템을 노릴 것인가, 수업을 지켜 주문을 배울 것인가."* — 이 긴장이 게임의 정체성이 된다.

| **시전 판정** | 숙련도 낮은 고위력 주문은 실패 가능 → 습득/숙련 시스템과 연결 |
| **약점 속성** | 적별 약점 주문 일반화 (현재 패트로누스-디멘터만 존재) |
| **보스 패턴 예고** | *"볼드모트가 지팡이를 치켜든다 — **다음 턴 강공격!**"* → 프로테고 선택 유도 |
| **연계** | 기절 상태의 적에게 공격 시 피해 증가 |

> **보스 패턴 예고가 비용 대비 효과 최고입니다.** 정보를 주고 대응을 요구하는 것만으로 전투가 퍼즐이 됩니다.

## 6. 성취·동기 설계

### 6-1. 이론적 근거

| 이론 | 적용 |
|---|---|
| **자기결정이론(SDT)** | 자율성 = 빌드·루트 선택 / 유능감 = 숙련도·난이도 곡선 / 관계성 = 동료 시스템 |
| **목표설정이론** | 일일 과제 / 학년 목표 / 기숙사 우승컵 |
| **몰입(Flow)** | 지역별 권장 레벨 표시, 난이도 자동 보정 |
| **가변비율 보상** | **희귀 드랍·지팡이 뽑기·강화** — 이미 3-2, 3-3에서 구조적으로 구현됨 |
| **Octalysis** | 소유(수집) · 희소성(한정) · 사회적영향(기숙사 경쟁) · 미지(랜덤) |

### 6-2. 구현 기능

- **업적 30~40종** — 각각 소량의 **영구 보너스** 부여 → 회차 동기
- **도감(Codex)** — 마법 생물 / 주문 / 아이템. 조우·습득 시 해금, 완성률 표시
- **칭호** — 조건 달성 시 획득, 장착 시 소폭 버프
- **일일 과제** — "탐험 3회", "수업 참석", "친구와 대화"
- **3학년 구조** — 학년당 메인 챕터 1개 + 서브 퀘스트 4~5개
- **New Game+** — 업적 보너스·도감 계승, 난이도 상승

## 7. 모바일 우선 UI/UX

- **하단 탭 네비게이션** — `[모험] [캐릭터] [소지품] [도감] [기록]`

- **상단 고정 상태바** — 체력·기력·마력·날짜
- **타이프라이터 텍스트** + 탭 시 즉시 완료
- **토스트/스낵바** — 레벨업·업적·드랍 (`alert()` 대체)
- **바텀시트 모달** — 아이템 상세, 확인 대화상자 (`confirm()` 대체)
- **희귀도 시각화** — 등급별 색상·테두리 광채, **전설 등급 드랍 시 전용 연출**
- **판정 연출** — 주사위 롤 애니메이션 + 성공/실패 색상 플래시 + `navigator.vibrate()` 햅틱
- **전투 HUD** — 데미지 팝업, 체력바 애니메이션, 상태이상 아이콘
- **퀘스트 로그 UI** — 진행 중 퀘스트 목록 (누락 시 길 잃음)
- **접근성** — 최소 44px 탭 타겟, 폰트 크기 3단계, `prefers-reduced-motion`, safe-area 대응
- **PWA 전환** ⭐ — `manifest.json` + service worker → **홈 화면 설치 + 오프라인 플레이**

## 11. Claude 실시간 활용 — 검토 결과

**결론: 실시간 호출은 권장하지 않으나, 사전 생성 방식이 훨씬 낫습니다.**

### 11-1. 실시간 호출이 어려운 이유

| 방식 | 가능 여부 | 문제 |
|---|:---:|---|
| 브라우저에서 Claude API 직접 호출 | ❌ | **API 키가 정적 사이트에 노출됨.** 공개 GitHub Pages에서는 누구나 키를 훔쳐 쓸 수 있어 절대 불가 |
| Claude Artifact 런타임 기능 | ❌ | 이 계정에서 사용 가능한 런타임 기능은 `downloads`, `mcp` **뿐**. LLM 텍스트 생성 기능은 제공되지 않음 |
| 백엔드 프록시 (Cloudflare Workers 등) | △ | 기술적으로 가능하나 **서버 구축 + 호출당 API 비용 + 오프라인 불가**. 개인 게임에는 과함 |
| 플레이어가 자기 API 키 입력(BYOK) | △ | 구현은 쉬우나 **일반 플레이어는 API 키가 없음**. 본인 전용이면 선택지 |

### 11-2. 권장안 — **빌드 타임 사전 생성** ⭐

실시간 호출의 이점 대부분을 **비용 0, 위험 0, 오프라인 가능**으로 얻는 방법입니다.

1. **대량 사전 생성** — 구현 단계에서 Claude(소넷)로 이벤트 120개+, 대사 변형, 아이템 플레이버 텍스트를 생성해 `data/*.json`으로 **정적 동봉**
2. **변형 엔진(템플릿 슬롯)** — 텍스트에 치환 슬롯을 심어 런타임에 조합
   ```js
   "{시간대}의 {장소}에서 {대상}이(가) 나타났다. {묘사}"
   // 각 슬롯당 5~10개 변형 → 조합만으로 수백 가지 문장
   ```
   플레이어 체감상 "매번 다른 문장"이 되며, API 호출은 0회
3. **조건부 반응 텍스트** — 성향·기숙사·호감도·숙련도에 따라 다른 문장을 미리 작성해 분기
   → *"슬리데린인 당신에게 그는 경계하는 눈빛을 보낸다"* 같은 개인화가 정적으로 구현됨

> 실제로 상용 텍스트 게임 대부분이 이 방식입니다. 실시간 LLM 없이도 "살아있는" 느낌은 **변형 슬롯 + 조건 분기**로 충분히 만들어집니다.
